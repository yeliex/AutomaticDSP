# 飞行与远端资源查询支持评估

状态：2026-09-25 静态审查，尚未实现新的飞行命令，也未进行游戏内飞行验证。

## 现有能力及证据

- `TaskCommandExecutor.Commands.cs` 的 `ExecuteMoveToLocked` 校验当前行星，以 `Vector3` 和 `OrderNode.MoveTo` 移动，并按局部距离完成。原生 OrderNode 只有局部 target，没有目标天体或宇宙坐标字段；不能复用为星际目的地命令。
- `PlayerMove_Fly` 会处理已有 MoveTo 订单，但订单距离投影到行星表面；现有 Mod 未显式提供起飞/降落控制。直接用三维高度作为现有 moveTo 的完成条件可能无法到达。
- 原生 `PlayerMove_Fly.GameTick` 在高度 >49、水平速度 >12.5 且 `mecha.thrusterLevel >= 2` 时进入航行；动力消耗由原生 UseFlyEnergy/UseThrustEnergy 计算。
- `PlayerMove_Sail.GameTick` 的曲速入口要求推进器等级 >=3、核心能量大于 `warpStartPowerPerSpeed * maxWarpSpeed`，并调用 UseWarper；按原生自动补充设置处理缺少翘曲器，不能直接置 warpCommand 绕过消耗。
- 当前 galaxy 摘要列出星系/行星基础属性，不能据此认定远端资源已按探索等级可见。
- 原生 `UIPlanetDetail` 要求：当前行星探索等级1、同星系2、玩家到行星宇宙距离 <14400000 时3，否则4；已有 factory 且等级>=1 有原生例外。只有 scanned 且可观察才汇总矿量/矿脉数。具体阈值随版本复核，不另写脱离原生规则的“全图矿物读取”。

本次原生代码审查摘录保存在本地 `.tools/flight-audit/`，不作为项目源码编译。

## 最小实现顺序

1. **按原生可见性查询资源**：扩展与行星对象对齐的查询，返回扫描状态、是否可观察和允许范围内的原生矿量/数量；不可见值返回明确不可用，不能填零。扫描复用原生流程，不生成远端工厂、不伪造已探索。气体、海洋与固体矿物分别遵守原生展示条件。核对通用原始对象查询，避免成为绕过可见性的新入口。
2. **飞行状态与星球内控制**：读取 movementState、所属天体、局部/宇宙位置与速度、径向高度、推进器等级、储能/恢复功率、航行及曲速速度、翘曲器库存。先追踪 PlayerController 的输入更新与状态转换，确定原生起飞、升降、着陆入口；不能直接篡改位置/速度/等级。现有 moveTo 保留局部语义，飞行控制独立定义。
3. **行星际输入**：提供有时限的方向、推进/制动和升降等玩家能力输入，或复用确有的原生导航目标入口。目标星球选择、动态方位计算、途中修正与燃料预算留给外部 Agent，不新增自动选星/自动航线策略。宇宙坐标使用双精度，并随天体运动刷新；不能把一次获取的位置当永久目的地。
4. **曲速控制**：复用按键入口等价的完整原生判定、翘曲器消费与开始/退出行为。不可用时返回明确原因。不得通过元数据快速旅行、传送或直接设置 warpState 替代正常航行。

上述为设计步骤，命令名称和参数尚未确立，不能写入已支持命令表。飞行占用机甲指令通道，与移动、采集及建造下达互斥；科研和手搓仍可并行。取消/超时应撤销 Mod 持续输入，不瞬间停速或强制着陆；返回真实飞行状态，让 Agent 决定后续行动。

## 验证完成依据

- 探测不足、扫描中、已探测有矿、已探测无矿分别返回正确状态；原始查询不能泄漏受限矿量。
- 未解锁不能起飞/航行/曲速；正常操作真实耗能，缺能或缺翘曲器按原生结果失败，失败不额外消耗。
- 星球内飞行、落地、同星系往返分别实测；越洋、气态行星与能源不足不伪造成功。
- 曲速启动/停止、翘曲器消费、能量变化、取消后的惯性及接近目标天体行为实测。
- 目的地判定包括所属行星与真实着陆状态；重载存档、用户手动操作或天体切换后，不沿用旧局部坐标和实体引用。
