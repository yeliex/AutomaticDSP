# 行星内生产闭环验收

本流程验证外部 Agent 通过现有接口建立并运行生产线。布局、矿区选择和材料预算由 Agent 决定，Mod 仍以游戏原生规则校验和执行。

## 验收顺序

1. 确认游戏版本、源码提交与已部署 DLL；从测试存档加载，并另存本次验收进度。
2. 查询当前实体、科技、库存、电网和机甲能源，确认没有其他执行中的任务。
3. 建立铁矿机、传送带、分拣器和铁块熔炉；逐条记录请求、任务结果与落成实体。
4. 安排产物去向，确认输入、输出、配方及供电连接。
5. 在不人工补料、取出产物或手搓铁块的情况下，观察至少三个连续生产窗口。
6. 铁块验收通过后，再逐步建立铜块、磁铁、电路板、磁线圈、电磁矩阵及研究站供料。
7. 蓝糖闭环以研究站持续消耗产线生产的矩阵，并实际解锁一项需要蓝糖的科技为完成依据。

建造任务 `SUCCEEDED`、设备工作、持续产出和科技解锁是不同层次的证据，应分别记录。缺失端口信息或原生校验拒绝时，根据现场和错误定位，不扫描 slot 或反复提交同一失败请求。

## 机甲能源

```graphql
{
  metadata { gameTick localPlanetId }
  mecha {
    coreEnergy
    coreEnergyCap
    reactorEnergy
    reactorStorage { items { itemId name count } }
  }
}
```

`coreEnergy / coreEnergyCap` 是核心电量比例；`reactorEnergy` 和燃料仓用于判断后续补能。燃料仓为空不表示核心储能耗尽。结合当前电量、预期作业消耗与补给距离决定何时补燃料。

## 连续产量记录

每个窗口建议覆盖至少 60 个游戏秒；记录窗口起止的 `metadata.gameTick` 和 `game.gameTime`，暂停期间不计为生产时间。

当前游戏 `0.10.35.29088` 的原生实现中，`FactoryProductionStat.GameTick` 把生产寄存器累加到 `ProductStat.total[6]`，消耗寄存器累加到 `total[13]`。`ProductStat.Export` 会保存这些累计值。升级游戏版本后需要重新核对。

通过 `localPlanet.factoryIndex` 定位 `production.factoryStatPool`，再以 `productIndices[itemId]` 定位 `productPool` 中的物品统计。索引为零表示尚未创建该物品的统计条目；字段读取失败或返回 `null` 不能当作零产量。

- 窗口生产量：窗口末累计生产量减去窗口初累计生产量。
- 窗口消耗量：窗口末累计消耗量减去窗口初累计消耗量。
- 平均产速：窗口生产量除以同一窗口的游戏时间差。
- 行星总量必须结合目标矿机、熔炉、分拣器和连接状态判断归因；其他产线或手搓可能干扰结论。
- 切换存档、重新加载、行星变化、游戏时间回退或累计值回退时，停止比较并重新建立基线。

三个窗口均有产出只能证明这一观察期内持续运行。需要更长续航时，另行核对矿量、输出容量、燃料及电力余量。

### 自动靠近的取消回归

源码检查发现 `entityFastTakeOut` 和 `transferStorageItem` 包含在交互范围之外下发移动订单的分支，但原取消清理分支遗漏了这两种命令。已补齐清理分支并通过构建，尚未部署或通过游戏内回归。当前存档 `buildArea = 80`，交互半径回退值和下发半径均为 80，无法触发该自动靠近分支；不能把源码发现表述为当前存档中已复现的故障。

回归步骤：

1. 确认队列为空，在命令下发半径内、交互半径外选择当前存档中的目标实体。
2. 提交命令，等待 `phase = approaching` 后取消。
3. 确认任务进入 `CANCELLED`，在游戏 tick 持续推进时观察玩家位置，排除只是游戏暂停造成的静止。
4. 检查取消后没有继续接近目标或发生新的物品转移；超时路径使用同一清理方法，也应核对。

### 建造验收暂停

更新 DLL 后，`task:1` 的移动与返回均成功。`task:2` 清理了候选位置周围 10 个植被对象，但 `task:3` 在同一矿机位置仍返回 `Collide`，没有建成实体。清理植被不构成碰撞原因的证据，也不应作为建造前置条件。按用户要求停止子代理和建造尝试，转为[建造碰撞排查](build-collision-investigation.md)。

碰撞问题后续已定位并修复：矿机遗漏了附近建筑碰撞体激活，造成重叠建筑漏检；原候选位置本身另有矿脉碰撞。联合查询版本后完成铁矿簇 9 台矿机、铜矿和煤矿各 1 台的原生建造验证，以及重叠拒绝回归，见[碰撞实测记录](build-collision-investigation.md#多矿区及密集摆放回归)。这些测试不代表已完成供电和输送建设。
