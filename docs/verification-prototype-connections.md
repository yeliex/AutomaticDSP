## 存档中的连接记录差异

同一暂停快照（gameTick `845413`）下，分拣器实体 `18 / 14 / 44 / 50` 的原生连接槽 `0` 均为零，但 inserterPool.insertTarget 分别为 `7 / 16 / 22 / 22`。15 个分拣器中其余 11 个的取放目标与连接槽一致，其中实体 `58 / 51` 的取物目标和输入连接均为零。

这是游戏对象中两种原始记录的差异，不是查询解码错误。后续定位到 `placeSorter` 未检查插槽占用，且可选坐标会绕过插槽解析；原生 `WriteObjectConn` 会清除目标插槽的旧双向连接。该机制与四处异常及目标建筑槽 0 已连接其他分拣器的现场记录一致。查询继续保留原始值，执行端增加占用检查及坐标一致性检查。
