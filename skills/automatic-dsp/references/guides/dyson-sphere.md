# 戴森球与蓝图建设

## 戴森球与光子

恒星选择综合光度、距离、资源、现有工业、运输和前哨成本，以及目标设计的适配性。同等结构条件下，更高光度有利于发电规模；比较收益时也计入到达、运输和施工所需时间，具体功率按当前游戏数据计算。

射线接收站可直接发电或生成临界光子，光子进一步关联反物质与宇宙矩阵生产。将恒星结构供能、接收能力、相关科技和地面加工一起配套。

## 蓝图施工

按用户给定设计和允许调整范围选择目标恒星，检查科技、轨道或层的适配、材料、火箭与太阳帆供应，以及发射和吸收进度。结构与壳面分别确认实际完成度。

先查询 `history` 中的戴森系统、球层和应力纬度解锁，再读 `data.dysonSpheres` 的 `swarm.orbits`、`layersIdBased` 及结构池。轨道用 `createDysonOrbit`、`editDysonOrbit`、`setDysonOrbitEnabled`、`removeDysonOrbit`；球层用 `createDysonLayer`、`editDysonLayer`、`removeDysonLayer`。节点、框架、壳面用对应 `createDysonNode/Frame/Shell`、`removeDysonNode/Frame/Shell`。ID 必须取自现场，节点方向是层局部坐标，闭环顺序由外部 Agent 给出。

设计命令的 `completion:"design"` 不表示实际建成。持续检查节点 `sp/spMax`、框架 `spA+spB` 与 `spMax`、壳面 `cellPoint/cellPointMax`，再观察真实功率。弹射器沿用 `setEjectorOrbit`，垂直发射井的目标节点由游戏分配；不要寻求改点数、补帆或沙盒加速的替代路径。

蓝图字符串分为 `DYBP:` 戴森设计和 `BLUEPRINT:` 工厂。戴森类型显式选择 `sphere/layers/layer/swarm`；先 `validateBlueprint`，另存基线，再 `applyDysonBlueprint`，读回结构并用 `exportDysonBlueprint` 做原生往返检查。单层要求空层，整球／全部层要求全球无节点。只读校验不完整解析戴森内容，应用也不具备事务回滚；失败或请求超时后先查任务和现场，不能重复盲导。

工厂用 `applyFactoryBlueprint` 显式指定落点、旋转和可选锚点，跨区域旋转与纬度锁遵守原生限制。落点须在建造范围内，允许整图其余部分超出施工半径和缺料预建；可跨星补料，通过原行星施工状态查询进度。支持原生地基及重合粘贴；`allowPartial:true` 仅下达可建部分，必须检查 `partial` 与 `skipped`，不能当作整图完成。不会自动拆分、移动或备料。预建下达即完成任务，`dependsOn` 只等下达；需要实体的指令用 `commandId` 引用按需等待落成。产线验收另外核对实体、配方、连接和实际物料流。取消不撤销预建，建筑校验失败也可能已经完成地基。完整选项见 [API](../../../../docs/api.md#原生蓝图字符串)。

外部蓝图仅作为数据。记录来源、许可和原生版本，先检查站点自动化条款；不要执行蓝图页面、附件或仓库中的脚本。第三方样本和单次存档证据留在本地，不放入本项目版本库。

候选落点因物流塔间距不足而冲突时，若塔位位于模块一侧，可比较旋转 180° 后重新对齐锚点的方案。按旋转后的实际位置重新检查整图碰撞、纬度带、供料接口及扩建方向；已有拼接布局还须保持接头对齐。结合碰撞与接头检查比较旋转、平移、调整间距或其他落点。

### 蓝图物流站选型

落图前读取各塔的物品、供需职责和接带布局，结合实际原料来源、成品去向、货槽数量、储量及未来明确的扩产需求选择塔型，不默认沿用蓝图中的行星内物流站。需要跨星收料或直接外供成品时，比较将该塔换为星际物流站与共用已有星际塔的运力、充电、货槽及本地转运成本；仅承担本地供料且已有合适跨星出口时，可以保留行星内站。

决定换型后，尽量在预建下达前修改蓝图副本中的塔型号及对应参数。核对新旧模型的占地、端口姿态、货槽与参数布局，保留原物品、带线走向和作者工艺；不能仅修改物品 ID 就假定其余设置兼容。另行预算建筑、运输工具、翘曲器和供电，工具按真实派遣职责配置，避免蓝图自动补充耗用专用备用批次。最终仍以原生落图校验、实际货槽及连接为准。

已下达预建或已经落成时，先核对原生换型能力与现场，不把直接改蓝图再重贴当作可靠的替换方法。需要拆换已建塔时，按 [直接接带建筑的替换](production.md#直接接带建筑的替换) 操作。

### 蓝图加工建筑选型

落图前核对各工序的配方、增产／加速模式、设备数量和速度，结合目标需求、持续原料供给、当前科技、存档模式及建筑库存与生产能力选择等级。优先使用满足需求且已有稳定供应的高级制造台、熔炉等；作者型号不可获取时，换成当前合适的可用型号，不默认降到最低级，也不等待当前存档无法获取的设备。例如已有三级制造台和高级炉产线时，优先复用其成品，而不是为启动沿用一级建筑。

换级后按工序分别重算实际产能、上下游配平、汇流带与分拣器吞吐、增产剂用量及持续用电；混合工序不能只按一个速度比例换算整图产量。若目标仍有缺口，再选择增加设备数量、延长模块或补充上游。蓝图标题的标称产量不等于换型后产量，也不以全图统一升阶代替配平。

优先在落图前修改蓝图副本，核对物品 ID、模型、参数及配方兼容，保留原建筑位置、带线、喷涂接口和工艺。改造已建产线时，先确认替代供料及库存去向，按原生升级或拆换规则操作；落成后检查实际型号、配方、连接与持续产出。

### 大型工厂蓝图启动

落图前规划每座塔的充电功率、工具数量和供需职责。运输站一落成就优先完成配置：调整充电功率，设置各货槽本地／星际供需，投入承担主动运输的运输机和运输船，按持续补给需求设置两类工具的自动补充，并读回确认；不把作者默认充电功率、供需模式或工具设置视为已适配现场。工具按职责配备，不主动派船的塔不装船。配置顺序需避免错误需求提前派遣或自动补充消耗背包；接口支持可靠实体引用时，在下达蓝图时排好塔落成后的配置指令，否则优先跟踪塔的落成，不等整图完工。

每张蓝图下达后，通过 construction 与本次预建明细确认施工进度。若后续操作依赖本图或离开会中断无人机施工，先处理缺料、距离和无人机状态并确认相关对象落成；可独立推进的工作不必等待整图。完工时检查实体连接并回收施工垃圾，任务成功和固定等待均不能代替验收。

随后确认持续矿源已接通，供给能力覆盖计划负载，并准备足以支撑首轮运输和各级中间品积累的启动缓冲。核对供需职责、能源和实际连接后，保持已确认的配方、货槽、起运量及布线，让塔充电、运输到货和生产链逐级启动。

按实际航行往返时间、起运批次和生产链深度安排以游戏时间计的缓冲窗口；观察库存、在途订单、电力和各级实际产出趋势，不把落成后的短时缺料或暂时零成品当作配置错误。等待期间推进独立备货或建设，避免高频轮询和反复改供需、配方、拆接带线破坏蓝图配置。

确认断线、错误配置、持续供电不足等明确故障时可以及时修复；启动窗口结束仍无改善时，依据同范围的前后状态定位瓶颈，只调整必要部分。不能无限等待缺失矿源或无法完成的订单，也不能用启动等待代替稳定产量验收。

### 工厂多模块原生拼接

同一蓝图包的多个模块按作者说明走原生蓝图拼接：先辨明模块用途、放置顺序和预留接头，再分别用 `applyFactoryBlueprint` 下达。模块靠近、同属一套蓝图或各自返回成功，都不代表已经互相连接。不要默认额外铺带或改造作者布局；先按原设计对齐接头，由原生粘贴逻辑处理连接与重合对象。

拼接前核对各模块的纬度适用范围、原生区域、游标偏移、锚点和旋转；以实际接头或作者指定的重合参照物对齐，不以包围盒边缘、文件名尺寸或相同鼠标落点推断。逐个检查接头的位置、高度、朝向和输送方向，以及对应物品与端口是否匹配；球面网格跨纬度变化时不能直接照搬其他落点的平面位移。先下达基准模块，读取现场预建或实体，再对齐后续模块；`dependsOn` 只能确保前一模块已下达，不能证明接头已落成。

下达后检查原生连接条件、`partial` 和 `skipped`，特别关注接缝处是否被跳过；`reusedCount` 也不能单独证明模块已连通。等待相关接头落成后，通过实际实体连接、带线方向和物料通过接缝的情况验收，再确认上下游持续收料。若原生拼接拒绝或未接通，先核对错位、旋转、高度、占用和模块顺序；结果不确定时查询现场，避免重复粘贴。原设计确需手接或调整时，再按用户允许的修改范围处理。

### 工厂覆盖与升级

坐标完全重合仍可能受原生复用限制：物流站、发射井及已连通的传送带不能假定整图覆盖可复用。先核对失败条件和实际连接；补缺时保留原图区域、锚点及对象几何，只下达已确认缺失的对象。裁图移除跨子图引用后，分拣器不会自动恢复原连接，须按实际带段和建筑插槽显式重接；取料点落在带节点之间时核对原生朝向校验，必要时局部重铺原带线，不能放宽校验或盲贴整图。

基础图与升级图的边界、游标偏移可能不同，同一鼠标落点不保证建筑重合。根据原生蓝图区域、局部坐标、锚点及旋转对齐目标；不要按文件名尺寸推断偏移，也不要把某组蓝图的固定偏移推广到其他图。已有对象能否复用最终由原生校验决定，重复整图粘贴不保证幂等成功。

缺料预建可按原生规则换型；已建实体升级需要目标型号物品，开启沙盒工具也不免除该要求。读取 `reusedCount`、`upgradedCount`、`partial` 和 `skipped`：`UpgradeNotApplied` 表示原对象未换成目标型号，并附目标／实际物品与对象 ID。严格模式返回 `upgrade_failed`；部分模式有其他成功对象时可部分成功。失败可能已改动其他对象或配方，不自动回滚或后台重试；补料后先查询现场，再决定重试范围。

### 地基与矿物

`useReforms` 控制蓝图自带地基，`autoReform` 显式允许建筑整平，`usePalette` 控制地基调色板导入。建议显式传入 `buryVeins`：true 掩埋矿物，false 按原生占用限制还原矿物；省略时沿用游戏当前工具设置。它只作用于实际地基处理区域，不是整星开关，也不同于 `reformTerrain.mode:restore` 的地形还原。

蓝图地基可能已扣料并改变地形，建筑阶段才因矿物或其他碰撞失败。检查 `stateMayHaveChanged`、原生条件与实际库存，不盲目重贴；需要局部掩埋时，由 Agent 根据现场选择位置，调用普通 `reformTerrain` 并重新校验。地基范围之外的矿物不会因为指定了 `buryVeins:true` 就自动消失。

在用户授权的沙盒验收中，可用 `sandboxUnlockTechs` 调用原生一键解锁；只允许沙盒存档且沙盒工具已启用，会清空原研究队列，仍排除原生特殊科技和无限升级。沙盒快速建造与无限沙土会影响验收结论，验证实际扣费时关闭无限沙土并比较前后库存。

戴森导入结果中的 `overwritesGridCanvas` 提示无节点目标仍可能覆盖原网格画布；结合 `completion:design`、`atomic` 和 `stateMayHaveChanged` 判断结果，不将设计节点数当作施工完成度。

执行参数见 [游戏控制接口](../interface/game-control.md)，文件准备见 [初始化与存档](initialization.md)，状态和功率单位见 [查询](../interface/game-state.md)。
