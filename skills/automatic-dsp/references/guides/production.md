# 产线建设与运行

规划成排扩建或多塔工业区时，可选读 [大规模产线布局](large-scale-layout.md)，参考选址、球面空间、建设顺序与邻塔布线方案。

## 场地和布局

行星表面的球面几何、建筑朝向、端口、地形和周边实体共同决定位置与连接。方案经原生建造校验后，核对实际落点。

抬高球面上的传送带时，将地面点沿径向整体缩放到目标半径，保持经纬方向；不能只增加半径而保留世界坐标的某一分量。比较不同高度对象的位置时使用完整三维姿态，不能直接把世界 Y 差当作南北间距。

建筑失败时按返回的实际预览 `position/rotation/modelIndex` 定位，不能把请求坐标当作吸附后的坐标。诊断缺少实际预览信息且无法定位碰撞时，先补全原生失败诊断，再继续施工，避免反复猜坐标试建。

已建对象也可通过 `localPlanet.physics.colChunks[].colliderPool` 读取原生世界坐标碰撞体，按 `objType`、`objId` 和 `isForBuild` 筛选。传送带实例的碰撞体覆盖实际连接段，不能用原型中的固定小框代替；将候选建筑的碰撞体变换到同一坐标系，预检与这些实例碰撞体的重叠，再提交原生校验。

碰撞体 `ext` 含负值时，不应跳过后就认定该位置无障碍；此时还需核对对应已建带段的实际位置、高度和连接，防止候选路线意外接入既有带线。转角报 `TooBendToLift` 时，同时检查附近是否有被自动匹配的已有带段，不只检查规划点列自身的升降。

密集工厂中规划带线或遭遇 `Collide` 时，读取周边实体的实际 `pos/rot` 与对应原型 `prefabDesc.buildColliders`。碰撞体可能有多个子框，且相对建筑中心偏移；由 Agent 按实体姿态和子框 `pos/q/ext` 换算占地并预检完整路线，留出传送带或分拣器自身宽度。用预检结果选择下一条路线，最终仍以原生建造校验为准。

靠近海岸时，先查询原生地形高度和建筑 `landPoints`，采样每个落地点及吸附余量，再决定整排布局。中心在陆地上不代表整个占地可建；`NeedGround` 优先排查落地点跨水面或低地，不要归因于植被，也不要自动铺地基绕过规则。查询契约见 [提示与地形查询](../interface/game-state.md#提示与地形查询)。

矿机选址综合覆盖点、剩余矿量、场地、电力、输出通路和带长。供电规划结合已有电网。重复设备可沿易扩展方向排列，为进出料和后续建设留空间；试建或批量建设取决于现场信息的充分程度。

抽水机采集星球海洋，不使用矿脉。先查 `localPlanet.waterItemId` 确定海洋物品（如水或硫酸；0 表示无海洋物品），并与建筑 `prefabDesc.waterTypes` 核对；不要按星球名称假定产物。结合原生 `landPoints`、`waterPoints` 和 `waterHeight` 检查岸边落点与取液点，最终保留原生 `NeedWater` 等校验。建成后核对采集组件实际产物及持续输送，不能在普通水海洋上指定生产硫酸。

先规划整条产线的建筑排列、朝向、端口、进出料带、缓冲和供电，再施工；不要逐个放置建筑后才寻找连接路线。布局按以下优先级取舍：

1. 保证原料持续送达、主副产物都有出口；建筑贴近对应带线，分拣器尽量一格。
2. 同工序建筑紧凑成排，共用直线进出料带；同品产出汇入公共缓冲，避免每台机器独立囤料。
3. 在原生地形、碰撞和吞吐允许的范围内缩小整条产线占地，保留必要的输送、供电与扩建空间。比较平面与立体方案，不能为了少一座电塔而明显拉长输送距离。
4. 拐弯用于避让矿区、地形或必要交叉；消除空地上的折返、反复偏移和可避免的绕路。减少拐弯是为了保持连续可建空间、缩短分拣距离和提高密度，不把拐弯数量本身当成吞吐指标。

选址同时检查矿簇及未来采矿机、出矿带的作业空间，抽水机、电塔和过路带也应避让。原生允许建筑或传送带覆盖矿点，不代表该布局适合后续开采。传送带经过矿区时优先评估抬高，给矿机及其出矿带保留地面空间；查询矿点和周边碰撞体，规划合法坡道、净空及取放料段，再与绕行比较，不能仅因地面带可建就穿过矿簇。

## 连接与吞吐

明确物品来源、去向和建筑端口。分拣器从来源取物、向目标放物；连接传送带时确认对应带段及流向。按建筑机制选择传送带直连或分拣器连接。

施工前可读 `items.prefabDesc.portPoses/slotPoses` 规划朝向；落成后通过 `factory.objectConnections(entityId: ...)` 重读实际模型端口、姿态和连接。传送带使用 `beltPorts.index`，分拣器使用 `sorterSlots.index`，保持原生编号；带段端点按原生特殊规则处理。AI 计算坐标及路径，任务完成后复查连接对象、槽位与方向，再观察物流。查询为空或实体已回收时重新观察，不能复用旧端口；详细契约见 [原型与连接](../interface/prototypes-and-connections.md)。

放置前先区分原生传送带直连端口与分拣器取放插槽，不把两者当作同一种入口。先确定原料来向和产物流向，再根据端口位置、朝向选择建筑 `rotation`，给直连带留出出口直线段和转弯空间，也让分拣器插槽尽量靠近对应带线。抽水站、油井、物流站等仅作为直连示例，实际能力以查询到的端口为准；不要先固定建筑朝向再绕长带补接。

不同建筑不能套用同一套插槽编号：例如化工厂的 8 个插槽分布在前后两排，并非制造台的四边 12 槽；研究站与制造台的左右槽编号也不同。每种建筑首次连接前读取 `objectConnections.sorterSlots`，用实际姿态换算端点与朝向；不能仅凭“槽 7 是南侧”“槽 4 是东侧”跨建筑复用。两栋建筑直接相连仍须计算实际端点距离，超出原生分拣器范围时用短带衔接。

多产物配方的输出分拣器显式设置 `filterItemId`。连续转运分拣器接同一条短带时使用不同带段，避免输入、输出重叠碰撞。

诊断制造组件的 `served`、`produced` 数组时，先查询当前配方的 `items`、`results`，按各自实际顺序对应物品；不能按记忆中的主副产物顺序判断缺料或堵料。例如等离子精炼的第一项产物可能是氢，须以当前配方数据确认。

确认缺料后，修补旧上游之前先比较已解锁的高效配方、直接采集来源和已有物流供应。例如硫酸可从硫酸海采集并经星际物流供应，不必优先补齐普通硫酸配方的石矿、精炼油和水。核对替代来源的持续产量、供电、运力及其他消费，优先接入可持续且整链成本更低的来源；只有替代供给尚不可用、确需过渡时才修复旧链。需求端配置成功不等于已供料，必须验收供应端运行、实际到货和消费端持续生产。

采矿机等设施可通过端口直接接出传送带；显式点列保留原生端口锚点，检查实体带段是否实际进入出料口，不能只验连接关系。普通加工设施通常由分拣器送入原料、取出产物。交叉输送可使用不同高度的传送带，同时核对坡度、端点和碰撞条件。

新建成排熔炉、制造台时，以实际插槽为起点，优先布置满足原生最短分拣行程的共用带线，再因多条供料带、碰撞或通行需要增加间距。不要固定在建筑中心外三格铺带后，用高速分拣器补偿距离。带与建筑中心相隔几格不等于分拣器行程几格：先核对实际端点距离及原生网格判定，试建一组，确认分拣器行程和吞吐后再批量复制；高纬度的网格宽度变化也要重算。

同时核对同排建筑之间的间距。用当前模型的 `prefabDesc.dragBuildDist`、`buildColliders` 和原生网格吸附确定紧凑排布，试建相邻两台确认实际落点及碰撞后再复制；不要把制造台的占地或固定四格步长套给熔炉，也不要把炉间空隙当作分拣器与带线所需空间。没有输送、避障或通行需求时不额外留空格；建筑排长和带线取放点随实际间距一起重算。

`dragBuildDist` 是二维方向间距，按建筑局部排布方向使用对应分量，不取 `magnitude` 作为中心距。以当地沿排布方向的网格长度估算最小整数步长，再核对旋转后的碰撞体和实际吸附落点；不要取整后额外加一格。例如当前电弧熔炉的两个分量均为 2.9 米，水平碰撞半宽为 1.45 米；在每格约 1.258 米的已验证南北排布中，三格中心距约 3.77 米已足够，四格约 5.03 米会多留一格。制造台 Mk.II 的方向间距为 3.82 米，同处则需四格；这些格数不能直接套到其他纬度、方向或模型。

架高带用于交叉和避让，与建筑堆叠不同。按球面径向高度规划坡道，给升降、转弯及接头保留空间；分拣器取放段应与实际插槽同高且姿态平直。端点、坡度、转弯或避碰抬升问题见 [传送带高度与转弯诊断](../interface/game-control.md#传送带高度与转弯诊断)。

不要把研究站等建筑之间的视觉空隙直接当作可穿越通道。查询实际碰撞体及完整路径，避免传送带穿过建筑体积；必要时移到建筑外侧，或在确有净空的高度跨越。建成后复核实际带段高度及连接。

拥挤区域按上节的实际碰撞体检查方法核对全部邻近实体及吸附位移，再比较穿越与绕行。

规划前查询目标物品 `prefabDesc.multiLevel` 判断是否支持垂直堆叠，不根据建筑名称或固定白名单推断。字段为 `null` 或缺失时先做字段发现，不能当作支持。支持堆叠时优先比较垂直扩建与平铺，再按[堆叠属性与实例检查](../interface/prototypes-and-connections.md#垂直堆叠)核对搭接点、类型兼容、旋转和当前顶层。堆叠可节省占地和底层供料线，但仍需核对科技层数上限、整叠吞吐与供电。使用 `placeBuilding.stackOnEntityId` 指定上方槽位空闲的实体，最终以原生建造校验为准，建成后检查上下层连接及实际工作模式。

相邻同配方建筑可比较分拣器直接转送原料与共用传送带，研究站、发电厂等应先确认原生可取出的物品及实际转送效果。直连可省带，但分拣器耗电，串联吞吐受距离和上游取料影响；核对后排持续供料，避免只凭相同配方推定能够转送。垂直研究站优先利用原生层间供料。

堆叠增加生产能力或储量，不会自动增加底层入口的带宽。多层储物仓、研究站扩高后，按整叠各物料的需求检查进出料带、分拣器与层间传递能力。若瓶颈在底层入口，比较升级带线与分拣器、增加并行带、通过架高带向上层分段供料或从上层取货；先查询目标层实际端口并确认原生允许连接，不能仅凭支持堆叠就假定任意层都可取放。

分层供料应明确每条带负责的物料、层组和流量，配套足够的上游产量及独立输送能力。例如整叠研究站需求超过一条带的容量时，可在原生允许连接的上层增加独立供料带，分担底层入口负载；从同一条已饱和的带分出多个高度并不会提高总带宽。建成后核对各层实际收料、生产或研究速率及输出通畅情况，确认吞吐提升，而不是只确认架高带建成。

传送带可布置在水面，跨水路线可用于缩短带长；不要把普通建筑的陆地占地要求套到传送带上。路线仍以原生高度、坡度和碰撞校验为准。

四向分流器可用于分配物料、设置输出优先级及筛选输出。共用原料同时供给多条产线时，结合科研、燃料和其他需求安排分配，并检查各出口的实际供料。

共享供给线按同一种物料组织。不同产物分别使用专用出口、过滤分拣器、传送带和缓冲；红蓝矩阵等消耗比例随科技变化的物品不混放在同一箱子后共用出箱分拣器。缓冲仓靠近消费端，在原生碰撞和连接距离允许的范围内缩短出箱钩爪，按各物料需求分别限制容量。

多产物出口设置过滤后，原来已经搬运或进入带线的错误货物仍需处理。下游储罐有空位而整条带堵塞时，核对入罐端实际货物是否与罐内物品一致；用原生取料或拆改返还清理已有混料，再检查上游缓存下降及目标端持续到料。快速取料可能同时取到多个物品，按返回的 `movedItems` 核对；一次取料或修改过滤成功不能证明整条带已经清洁。

按整条产线的总需求、配方速率、设备速度与增产效果计算设备数量，再分配共享供料；不要固定复制“一炉一机”或“一炉一电站”。通过实际吞吐和缓冲变化验证配比，避免大量独立设备各自囤料而下游仍缺料。

汇流线路按总需求计算吞吐，分拣器能力结合等级、搬运距离和堆叠状态核实。扩产时同时检查运输容量。新增原料汇入共享带时，核对流向，将汇流点放在需要补料的取料点上游；从下游尾段接入不会向上游回送。验收同时观察汇入后的物料前进和各消费端实际收料，不只检查连接存在。

循环物料同时核对入口补料、各回流汇入点的带上空位、回流终点的接收能力和净剩余物料出口。过快的外部补料或已满的回流缓冲会堵住副产物出口，使循环生产停滞；可按净需求限制补料，并为净剩余物料安排持续消耗。扩大缓冲只能吸收启动积压和短期波动，不能解决长期净过剩。

分馏塔（俗称“重氢转转乐”）按一定概率将通过的氢转化为重氢，未转化的氢继续输出；产能取决于实际通过量与分馏概率。在原生处理能力、供电和输送允许的范围内，更快的传送带、足够的带上氢量和更多分馏塔可提高产出；不能只按普通配方时间估算，也不能假定塔数增加必然按比例增产。

扩产前也比较给氢喷涂可用增产剂：当前原生分馏按输入增产点提高成功概率，未转化的氢保留增产点回流，循环带吞吐不等于每分钟需要重新喷涂的数量。预算包括初次喷涂循环库存与后续净补氢，按实际增产点、概率倍率、工作耗电倍率和增产剂供应核算；不能只增加塔数，也不能忽略喷涂带来的额外用电与上游材料消耗。

优先采用紧凑且回流畅通的循环布局，可选多塔串联、分组短循环或单机小循环；氢出口回流到对应入口，重氢从各塔独立出口汇入专用带引走。串联长度与并行扩建可参考 [重氢分馏的循环模块](large-scale-layout.md#重氢分馏的循环模块)。优先接收回流，再用外部氢持续补足净消耗，避免补料挤占回流空位。扩产时一起核对循环带实际速度、各塔氢通过量、供电和重氢出口吞吐；优先升级真实瓶颈，再增加塔数或拆分循环。

分馏常用于消耗多余氢，重氢产出应优先安排持续消耗，例如燃料棒或后续生产；确保重氢出口畅通，避免重氢积压停塔、氢无法消耗，进而堵住上游化工产线。与气态行星等其他来源的重氢共用消费线时，让分馏产出优先进入消费端，外部来源补足缺口，避免外部供料填满入口而分馏出口仍堵塞。储液罐只能吸收短期波动，不能代替长期消耗；按氢的净剩余量和重氢需求安排规模。

若分馏循环已经堵满、分馏塔输入与氢输出缓存同时满，仅改回流优先级可能无法恢复；可通过原生取料从回流带取出少量氢，释放空位，再观察多个生产周期，确认无需反复人工取料仍能持续产出重氢。

已有线路发生运输瓶颈时，优先比较升级传送带或分拣器与增加并行带线、重排布局的成本。区分上游产量、带宽和分拣器搬运能力，升级真实瓶颈；结合科技、材料和耗电决定，避免用升级掩盖缺料或断电。

已有长距离分拣连接满足吞吐时，不必仅为缩短距离拆改；调整时保留合法端口和进出料通路。

下游缺料且取料端持续有料、设备供电正常时，检查分拣器距离、搬运周期、过滤和连接方向，将实际搬运量与设备需求比较。确认运输受限后，再比较缩短距离、升级或并联的成本；取料端也缺料时沿上游追查。改造后比较相同供电条件下的到料量和实际产出。

跨行星和星际供应还需考虑供需配置、运输工具、能源、距离及往返延迟，并用缓冲吸收运输波动。评估远端方案时计入前哨准备和持续补给成本。

## 建造与拆改

长带或成排建筑施工时，让机甲沿施工区分段前移，缩短无人机往返距离；站位兼顾待建对象、通行空间和后续施工方向。建造创建预建后释放机甲通道，后续 `moveTo` 可在 `waitingBuilt` 期间跟进。合理分段并选择靠近待建点的停留位置，避免过早远离导致无人机往返增加或停止施工；连接等实体依赖仍等实际落成。站位和分段由 Agent 规划，仍遵守原生下发范围与建造规则。

跟进移动应排在长带预建下达之后、依赖整条带落成的分拣器等命令之前。若先排入等待依赖的连接命令，后续移动可能被下达顺序挡住，机甲停在远端使无人机持续长途往返。施工明显变慢时，比较连续观测中的待建数量、无人机状态、距离和能源，再决定调整站位、分段施工或研究建造无人机升级。

离开施工区去远处采集前，先核对 `construction` 和建造任务；若当前范围内仍有待建对象，让离开命令显式依赖建造完成，或先在施工区等待无人机收尾。遇到施工超时，先读取仍保留的预建和实际实体，返回施工范围完成原生施工，不重新提交相同布局造成重复预建。

区分设计、等待建造和实际落成，随后验证配方、连接、供电与产出。布局验收同时检查整条产线占地、分拣距离、带线是否无故绕行，以及矿区和扩建空间；不能只以逐条连接成功作为完成依据。拆改时考虑相邻电网、输送与下游供应的影响，完成后复查连接和回收物品。

矿脉耗尽或设施被新产线替代后，可拆除确认不再使用的建筑及其专用传送带、分拣器等配套，回收材料并释放空间。先核对矿机覆盖矿脉的剩余矿量、设备用途和实际连接，沿闲置支线检查到仍在使用的汇流点为止；保留共用带线、缓存及仍有供电用途的电塔。若下游仍需供料，先验证替代来源已持续到料，再拆旧设施；缺料、堵料、缺电或短时停产本身不是废弃依据。拆除后确认没有误断供料或电网，并核对回收物品及落地垃圾。

修复断链后，沿物料来源检查到上游设备和缓冲仓，恢复拆改影响的供料。验收自动生产时停止手动补料，按游戏 tick 观察多个连续窗口的产出变化；分别报告连接修复、自动供料及库存续航，不能用一次手持投料的成功代替自动产线验收。

## 物料供应与仓储

本地持续供料和附近产线之间的交付优先使用传送带，规模化、跨区域或跨星球运输优先使用已解锁的物流塔。同一种产物的相邻制造台、熔炉等共用出料带；下游可直接接共享产物带，需要缓冲时，本地固体使用集中单品仓、本地液体使用储液罐，星际供应直接汇入物流塔。按汇流后的总吞吐核对带线、缓冲进出口和塔口容量，超出容量时分成独立带线或产线组，不默认复制“每台机器一个箱子加配送器”。

星际供应的物品直接汇入物流塔，以塔内货槽作为缓冲，不额外串接箱子或储液罐；固体和液体均遵循此原则。本地液体消费确有缓冲需要时使用储液罐，不用储物仓缓存液体。启动阶段塔尚未建成时记录临时出口，塔接通后转移旧库存、验证持续入塔，再移除临时缓存和专用分拣器。

本地固体缓冲箱放在连续传送带旁，按需要设置短分拣器一进一出，不把“入箱再出箱”串成主供料的必经路径；停电或箱满时，传送带主干仍须贯通。同物品的相邻产线共用主干和必要的单品缓冲，机甲补给共用配送点，不通过多个需求箱层层转送。已使用物流塔时，生产直接入塔、塔直接出带供消费端，以塔货槽缓冲，不再串接箱子。

燃料供应须验证从有效库存到发电机的整条路径。传送带和塔出口贯通不能替代发电机入口分拣器的供电；保留可再生或储能等启动电力，并按原生低供电运行条件验证恢复能力。分拣器尽量使用最短可用跨度，依据实际插槽、端点角度和碰撞校验布线，不用长分拣器弥补未核对的布局。

使用物流塔的供应点按未来大规模需求超前建设：成批布置当前最高可用设备，预留完整设备排、并行出口、塔口与电网扩容空间；材料到位后按整组投产，不按眼前缺口逐台补设备。配方和吞吐预算用于检查原料、电力、带线及运输是否支撑规模，不把精确配平的当前需求当作建设上限。塔内缓冲达到阶段目标后允许原生停产，后续需求增长时恢复供给；超前建设仍须落实矿量、持续能源和物流能力。

物流配送器主要用于机甲按需补给。同一供货片区的同一种产物通常只需在集中缓存上配置一个配送器；同产物多台设备共享这个供货点，不逐台安装。箱间配送只用于经吞吐核实的低流量、临时或分散补充，不能代替大规模物流主干；先按实际范围、运量、航速、往返时间、可用机器人和缓冲核对需求，持续需求超过能力时改用传送带或物流塔。

新建、接管蓝图或调整已有配送器时，所有指定物品的配送器默认设置 `playerMode:Both`，同时向机甲供应和回收；箱间 `storageMode` 按产线供需独立设置。原生“全部回收”（`itemId:-1`）专用模式只允许 `Recycle`，不能强设 Both。机甲需要的配送物品通过修改机甲物流仓库（物流背包）的物品与补货／回收阈值更新，不为每次取料反复切换供货点模式或直接从仓库手动取货。具体补给流程见 [能源与背包](mecha.md#能源与背包)。

改造已有逐机箱子与配送器布局时，先接通共享带、集中缓存及下游交付，验证整组设备持续出料和消费端收料，再回收冗余箱子与配送器，保留必要的机甲补给点。

配送器不能安装在储液罐上。液体主干使用传送带或物流塔运输；本地缓冲按需使用储液罐，星际供应直接使用物流塔货槽缓冲。

堆叠储液罐用于扩充容量；接带前查询实际实体的 `beltPorts`，不能把原型端口直接套到上层罐。上层罐可能没有输送端口，此时从有端口的底层罐或已有液体带接出，再按现场连接、吞吐和共享用料安排分流。

物流配送器放在储物仓最上层，以 `stackOnEntityId` 指定；继续叠箱会抬升配送器并更新连接。配置物品、机甲配送模式、箱间 Supply/Demand 和机器人后，供货箱选择、配对与发货由游戏完成。按当前 `history` 范围、电力、`pairCount` 和实际收货判断是否运行，接口见 [游戏控制](../interface/game-control.md#配送器物流背包与指定转移)。

建筑超市优先利用现有生产线附近的单品缓冲箱备货，无需为备货单独建立生产线；缺少对应产出或现有余量不足时再新建、扩产。机甲补给点配置物流配送器，自动供应和回收中间产物、建筑和运输工具；分流备货时保留下游科研和生产所需供应。依据当前建设阶段调整物流背包同步物品与补货／回收阈值；先查询实际已解锁格位，替换物品前取空原格位，避免沿用过时清单挤占背包和供货库存。核对配送范围、往返吞吐、电力和实际到货；超出范围时优先进入配送范围或通过物流站送到当地配送点，运量不足时排查并补足配送能力，避免退回逐箱手动取料。

使用建筑超市蓝图时，按作者说明区分生产、供应和接收模块，核对既有设施、地形、蓝图纬度锁及配送范围；不能将供应塔原配置直接视为接收配置，也不能将无配送器的模块视为已经具备机甲配送。生产与接收节点的位置和星球分工按当前存档的目标与约束决定。

物流塔、物流运输机和运输船等扩张建筑先查询已有基地的成品库存、制造设备和中间品供应。反复或大批需求在工业星建立正式、可持续的集中制造产线，再运到资源星部署，不在每个前哨重复临时冶炼、化工和递归手搓整条建筑材料链。仅在首次启动且已有供应确实不可达时使用必要的临时设施，记录退出条件；集中供应接通后回收已闲置的设施。

补料时综合可用库存和现有生产。取料前考虑库存对关键产线的保障作用，为研究、建造和机甲取料保留明确的材料预算。仓储按材料用途组织，作为供应和运输波动的缓冲。

持续供应由生产或运输补充，库存可维持时间按可用数量与净消耗速率估算。扩产时检查共用库存被哪些产线消耗，以及补给速度能否覆盖总需求。

## 工厂供电

### 能源选择

电力短缺时，始终先复核当前已解锁且能够落实供应的发电方式和燃料，检查是否存在更高效的可用方案，再决定提高发电量的措施。既有设备数量和开局燃料不应限制候选；新燃料需扣除科研等用途的需求，按可持续供给比较收益。

新增或扩充供电前，比较当前已解锁且能落实供给的电源，优先选择当前条件下效率最高的方案；不能因为风机易造、无需燃料就持续复制风电。效率按目标所需的持续净供电、单位占地、建设及运行资源成本评估，计入加工、运输耗电和日照等波动；单台额定功率或单件燃料热值不能独自证明最优。风电适合其条件确有优势或短期启动的场景，新能源解锁、燃料链建立或供电瓶颈出现时重新比较，并在更优供给稳定后替换旧方案。

火电燃料优先评估已解锁且能持续供应的更高级燃料。煤直接燃烧只作为开局或断供时的临时方案；具备加工能力后优先升级为石墨，并继续评估后续燃料。比较时计入加工耗电、原料成本及持续产量，不能只看单件热值。切换前接通新燃料并验证供电，再停掉旧燃料输入，让机组消耗已有缓冲；科研原料与燃料分别核对供需，避免互相抢料。

火电启动投料前核对背包中的可燃物；原生快速填入可能选择碳纳米管、石墨烯或增产剂，不能假定会优先取煤。指定燃料时使用专用缓存和过滤分拣器，少量手中投料按返回的 `movedItems` 核对实际数量；拆出一整叠到手中不代表一次快速填入会接收整叠。太阳能启动点应检查夜间实际供电，并为采液、化工与燃料运输落实持续补电。

由当前游戏物品和发电建筑数据取得候选，结合以下因素选择工厂能源：

- 目标设备允许的燃料类别与使用条件；
- 热值、发电效率、持续功率和发电条件；
- 解锁状态、现有库存、加工成本和其他生产用途；
- 获取距离、运输容量和持续补给速度。

比较收益时计入发电设施及燃料产线的建设和准备时间。

### 火电接力供料与燃料升级

成组火电站优先比较接力供料布局：建筑紧凑成排，用分拣器从前一台的燃料槽向后一台传递燃料，一条进料带可供应多台电站，减少为每台单独铺带的占地和改造工作。接力通过实际建筑插槽和分拣器完成，不是假定相邻电站会自动传料；先查询可用端口，并以原生连接校验和实际传料为准。

按整组满载燃料需求核算入口带宽，链上每段分拣器要承担其下游全部电站的消耗，并留出启动填充和恢复供料的余量。新建或扩长后观察首端、中段和末端燃料库存及实际出力；前端有料不代表末端供料充足。接力过长或搬运能力不足时，比较升级分拣器、分段补料和并行分组，不把单条接力链无限延长。

优先从共用燃料入口切换更高级且兼容的燃料，复用原有接力连接；核对所有相关分拣器的物品过滤，避免仍只允许旧燃料。先确认新燃料能持续供给，再停止旧燃料输入，观察旧缓存消耗和新燃料逐段进入。单位有效热值更高的燃料，在相同供电负荷下通常能维持更久、降低每秒物品流量和传送带／分拣器压力；这不等于单台电站额定功率同步提高，仍要计入燃料制造、运输及原料成本。

燃料方案同时评估增产剂喷涂。可在共用进料段集中喷涂，利用燃料增产效果减少达到同等供电所需的燃料数量；按当前游戏的燃料适用性和增产等级计算有效热值，不套用制造配方的产量或耗电倍率。计入增产剂生产与运输、喷涂设施耗电，并核对增产点在接力过程中保留、末端收到已喷涂燃料；最终按相同负荷下的实际燃料消耗和净供电确认收益。

### 电网运行

分别观察理论能力、实际出力、电网需求、覆盖与储能。局部电网连接、燃料供应和发电条件共同影响持续供电。

规划覆盖时包含机器、所有进出料分拣器和物流配送器。验收分别查询这些实体的电力组件与 `networkId`；长分拣器的耗电点可能在机器覆盖范围之外，主机已经并网也要检查取货端与出货端。

把发电容量与供电覆盖分别规划：按整组设备的负载和现有余量配置发电设施，用输电塔把电力传到生产区并覆盖多台建筑，不按每台生产建筑配一台风力发电机。读取实际连接距离、供电范围和现有电网，优先复用覆盖，在保持连通和设备供电的前提下减少电塔数量；电塔只扩展输电与覆盖，不能补足发电功率。

卫星配电站优先用于大规模产线的集中覆盖。只为小区域内少量建筑供电时，优先复用已有覆盖或使用普通电力感应塔；不能因卫星配电已解锁就默认使用，避免浪费建设材料。按实际连接距离与供电范围确认普通电塔能够覆盖全部耗电组件。

风机之间还有原生间距限制，碰撞体互不重叠不代表可以紧邻放置。批量布置前验证实际落点的风机间距、完整陆地落地点与并网距离；原生提示风机间距不足时调整间距，不反复复制同样的密排方案。

相邻且供电需求一致的生产区优先合并电网，共享发电余量、减少重复设施，便于统一检查。燃料生产、启动保障或确有独立供电需求的区域可分网，明确每个电网的电源、负载与边界，避免无目的地拆成多个小网。合并前核对合计供需及短缺影响范围，分割前确认各网有足够的独立电源；建造或拆改电塔后复查实际电网归属、连通与覆盖，避免意外合网或断电。

新建生产区预先规划与已有稳定电网的连接，可从已有电网侧向施工区延伸，结合施工顺序提前接通供电。核对实际电网归属、覆盖和供电余量，让完工区尽早投产；距离较远或有独立供电需求时按现场条件取舍。

燃料生产若依赖短缺的主电网，可能进一步降低发电供给。可按现场需要配置燃料缓冲或独立供电。发生这种连锁短缺时，先利用库存燃料或独立电源恢复燃料生产与输送，再逐步恢复其他负载；扩产前比较新增耗电和燃料链的持续供给能力。

## 基于统计优化产线

查询参数、单位与完整示例见 [分析面板统计](../interface/statistics.md)。先选择目标端指标，例如矩阵持续交付、实际 hash/秒或指定恒星戴森功率，再围绕限制该指标的链路诊断。

1. 建立基线：记录存档、`gameTick`、范围、窗口、目标物品产消、库存和电力供需。用短窗口识别近期变化，较长窗口检查持续性；刚投产或改造后的窗口混有旧数据，不能立即作为稳定效率。只查询相关物品，详细曲线按需展开。
2. 区分产能不足和产能未被利用：参考产能与库存来自原生缓存，`productionExtraInfo.freshness` 为 unknown；先用实际产消及相关设备、容器核实，不因缓存零值就判定没有库存或产能。参考数据与现场一致且实际产量偏低时，再结合缺料、堵料与电网证据找原因；参考产能不是承诺吞吐。产消相等可能只是上游供应限制了下游，不能据此判定目标需求已满足。
3. 沿物料链核实限制：按下方 [定位瓶颈](#定位瓶颈)表检查具体设备、库存及输送。星系内部运输不出现在跨星系进出口中，全局进出口 null 也不是运输为零。
4. 比较可执行改造：连接修复、物流升级、设备升级、配方切换、增产、电力补强或扩产。结合预计目标端净增量、材料、耗电、施工和停产时间排序；只提升非瓶颈设备的理论产能通常不能提高目标效率。保留必要施工物料与燃料缓冲。
5. 复测：新供给稳定后再停旧线；改造完成、自动供料恢复后，以相同范围与窗口比较目标端实际产出／科研速度、库存趋势和耗电；等待窗口覆盖改造后运行，或用累计量差和游戏时间差单独测量。避免混入人工投料、取料、跨区运输或其他同时施工的效果。结果未改善时根据新证据重新定位，不继续复制同一改造。

库存续航可用“可实际取用的库存 ÷ 已确认的持续净缺口”估算；分析面板 `storage` 还包含设备缓存和玩家物品，先确认可用部分。吞吐突发、运输往返和副产物共生会让短窗口失真，需结合连续窗口及具体设备状态判断。单条产线的贡献不能仅用整颗行星汇总归因。

### 配方与增产

改造涉及配方时，先做 [配方候选复核](goal-planning.md#配方候选复核)，再用 [产线需求计算](production-calculation.md)核算机器取整、原料及增产剂消耗。

切换配方后，同时核对旧输入缓存、配送器供需和分拣器过滤。仅开放一个自动化格位的箱子可能被旧料占满，使正确的新料停在分拣器手中；先关闭不再使用的供料需求，检查在途旧料和实际库存，再取回旧料或回收无用配送器。确认新料进入设备并产生实际产出，不能只凭配方和过滤设置成功判断改造完成。

### 定位瓶颈

以下现象用于步骤 3 的现场核实；改造候选按 [效率复核](goal-planning.md#定期效率复核)比较。

| 现场现象 | 优先检查 |
| --- | --- |
| 配方为空或没有工作目标 | 配方、设备兼容性及解锁 |
| 缺料 | 短缺原料的产消与库存趋势、供电、取料端物料及运输吞吐；取料端有料时重点查连接和分拣器 |
| 输出堵塞 | 主产物与副产物出口、仓储容量、下游需求 |
| 工作进度普遍变慢 | 电网供给、燃料链和供电覆盖 |
| 部分设备缺料 | 分配方式、汇流竞争与连接 |
| 库存持续下降 | 上游持续供给与实际消耗的差额 |
| 矩阵充足但研究慢 | 送达情况、研究模式、材料组合和研究能力 |

多产物配方需同时安排各输出去向；任一出口积压都可能阻塞整条线。仓储可暂时缓解波动，长期方案取决于净供需。副产物用于发电时，计入实际电力负载对燃料消耗的影响。
坐标、端口和存储状态见 [查询](../interface/game-state.md)，建造、连接、配方设置及物品取放参数见 [游戏控制接口](../interface/game-control.md)。
