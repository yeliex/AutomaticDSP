# 外星资源、运输与规模化扩张

## 先探测，再决定去哪里

开局母星通常没有可开采的钛、硅矿脉，但应以当前存档可见资源为准，不能仅按星球类型推断。先读当前科技、`history.universeObserveLevel`、机甲推进器等级及星系/行星状态，再比较已探测候选的钛、硅、铜、铁、煤、海洋、供电条件、距离和威胁。没有探测权限、扫描未完成、没有加载工厂和真实矿量为零是不同状态；未知不能按零处理，也不能通过种子或原始对象绕过探索科技。

矿物总量用于选星；落地后再读矿脉位置与剩余量决定矿机布局。天体 ID、宇宙坐标与行星局部坐标分开使用，实体 ID 只在所属工厂有效。选星、落点、规模与物料调度由 Agent 决定；指定目的地的飞行控制可交给 `navigateTo`。

距离不是唯一因素，优先比较建立持续供应及后续扩产的效率。首次扩张尤其要核对启动供电、燃料能否持续供应、建设成本与维护频率；没有风的固态星可能需要太阳能及夜间保障、可用的地热条件或外运燃料，未必适合作为首个前哨，但结合空间、资源与后续能源能力仍可能适合工业基地。地热方案先核对科技、设备与实际地形。原生 `windStrength` 是直接发电倍率：0 表示风机不发电，1 表示额定功率，不能解释为额外加成。

## 第一批钛与硅

母星即使没有硅矿和钛矿矿脉，散落的石头中体积较大的往往能采到一点钛矿和少量硅矿；这只适合少量补缺，不适合作为主要获取途径，也不保证每块石头都有掉落。核对采集对象与实际背包增量。低效补硅路线是石料→硅石→高纯硅块，不是玻璃；按当前配方查询投入、产量、耗时和增产效果，再比较本地加工与外星采矿的成本。

具备宇宙航行后，优先评估附近行星的天然硅、钛矿，而非持续扩大低效的本地补硅设施。第一次出航携带采矿、供电、熔炼、连接和单品缓冲所需建筑，并准备适用的高等级燃料及返程储备；留出带回货物的背包空间。前哨发电方案按当地条件与已解锁能力选择。

优先在产地将钛矿加工成钛块，再搬回母星；硅也比较加工为高纯硅后的携带效率。按当前配方、堆叠上限、目的地用途和前哨电力计算每格有效货量，不假定所有加工都更省格子。首批带回数量应覆盖目标科技、黄糖前置、物流塔和运输船等启动成本，并留建设余量；避免把全部钛投入科研后无料建立物流。

## 从人工运输转为持续供应

按实际科技前置推进星际物流，区分行星物流站与星际物流运输站。先准备物流塔、运输工具、必要中间品、派船站充电和两端生产设备供电，再建立供需设置，以塔内货槽缓冲星际供应物品，不额外串接箱子或储液罐。供应点按 [物料供应与仓储](production.md#物料供应与仓储) 的原则成批超前建设。同星系运输不必等待曲速能力；跨星系则评估航行时间、翘曲器供应与运输相关升级。

使用 `setStationStorage` 配置货槽及本地/远程供需，`setStationVehicles` 从真实背包放入或取回闲置运输工具。输出带创建时必须一并指定 `filterItemId`，输入带按原生货槽接收。核对充电功率、起运量和实际运输记录，验证目的地库存持续恢复后再降低人工搬运频率。供应方或需求方任意一边有运输船即可承担运输，无需两端都配置；再按吞吐、供电和往返时间决定数量。快速填充运输站会补运输工具，不能当作指定货槽填料。

前哨燃料等低吞吐补给先按当前单船运载量和原生起运百分比计算等待时间，并与接收端剩余燃料续航比较。满载起运会导致启动等待过长时，通过现有接口或原生物流站窗口调整派船站的起运量；百分比不是固定件数，运输容量升级后重新核对。设置后分别确认各目的地实际到货、持续供料及供电恢复；派出一艘船不能代表全部前哨都已补给。

运输机、运输船从所属派出站的储能支付运输能量，不需要在另一端补充燃料。原料供应星球的电网通常难以承受星际物流站的充电负荷，一般由需求方充电并派出运输船；产地供应站不放运输工具、不接电，作为被动收发货站，产地矿机、熔炉和分拣器仍需正常供电。根据两端实际供电余量和运输需求决定例外；若产地站也承担主动派机或派船任务，则必须为它供电，不能把“产地站无需供电”当成通用规则。

接电站先用 `setStationChargePower` 设置原生允许的最低充电上限，再结合运输频率、往返耗能、储能恢复和电网余量调整；最低上限不保证满足任意吞吐。充电上限不是固定耗电，也不是供电预算必须达到的发电功率；按实际充电和储能变化判断，避免为了匹配上限盲目扩建电源。被动站不接电与接电后设最低上限是两种方案，最低设置仍可能造成充电负荷。

物流站启动时，即使现有供电能力低于原生最低充电上限，也可接受短时充电需求超过电网供电能力，或先用独立小电网限制实际充电功率；不能因此判定物流无法启动。前者观察全网供电比例及产线、科研受影响的时间，后者确认独立电网没有被电塔自动连入主网；两者都以实际储能增长、派船耗能和货物到达验证启动效果。记录临时电网及恢复条件，在发电扩建、运输需求增长或货槽持续缺料时复查；主网已有余量而派船站仍因充电缓慢缺货，应尽快并网，不能长期保留启动限流。并网后核对供电比例、站内储能、派船及实际到货，并按持续运输的能量需求调整供电和充电上限。

本地铜、铁也会因科研、建筑和燃料链扩张而短缺。持续观察矿量、采集吞吐和库存变化，提前建设替代矿区或外星供应，不能只关注钛、硅。短缺先区分枯竭、矿机覆盖、供电和运输瓶颈。

氢与重氢需求显著扩大时，按实际条件比较气态采集、现有分馏的输送或喷涂升级，以及新增分馏，不预设扩产顺序。计入氢的净余量、重氢缺口、本地电力、增产剂供应、建造材料与准备时间，以及星际运输成本；分别比较新增持续交付和目标端收益，不只比较单台产量。气态采集适合当前需求时，让石油优先回归精炼油、塑料、有机晶体等化工用途，不默认持续扩建石油链来获取氢。核对可探测气态行星的实际产物和采集速度、轨道采集科技、采集器启动材料及运输能力，再比较扣除采集器自身燃料消耗后的持续净产量；并非每颗气态行星都产重氢。气态供应建立并验证到货及下游持续收料前保留必要的原供应：逐项核对需求站货槽、输出端口的物品映射、带线连接和实际出料，站内已有库存不代表氢或重氢已经接入产线。仍按实际供需处理石油化工副产氢。

## 跨星球产线规划

新建复杂产线或大规模扩产时，主动检查已探测星球的资源和现有产能，评估进口高级原料、替代资源、大规模基础原料或中间品，减少本地工序、设备、占地与布线。不等母星资源耗尽或空间不足才扩张；同星系物流不必等曲速。矿区续航接近新供应建设周期、当地布局需要大量填海或拆迁时，提前安排替代供应。

比较本地完整加工、进口原矿集中加工、进口材料或中间品的整条链成本：省下的建设时间和布局成本，对照新增前哨、供电、物流塔、运输工具、充电及翘曲器补给。按其他用途扣除后的可用产能判断增供能力，不能只看现存库存。

优先评估产地冶炼后运输，以降低货运压力；减量收益取决于实际配方，等量转换本身不减少货量。奇珍矿物、目的地已有大规模加工余量，或产地供电与施工困难时，也可进口原矿集中加工。奇珍资源按替代配方确定加工环节，并非都经过熔炉。

选定来源、去向和目标吞吐后，配置持续采集、供电、运输工具及充电方，核对往返周期和缓冲。缺少能力时先安排准备任务；新供应实际到货并持续供给后再停旧线。加工边界确定后，按 [大规模布局](large-scale-layout.md)安排目标星球的设备与物流塔。

## 后期选址与奇珍矿物

大规模产线按目标吞吐选择有足够建设空间、可持续能源、合适海洋和资源供应的行星；结合运输距离、物流吞吐、战斗威胁和维护成本分配采矿前哨、冶炼与成品生产。不要把母星的零散开局布局无限复制。

探测到奇珍矿物后，从当前已解锁配方比较其替代链，核对设备、总原料、耗电、运输与矿量续航；例如天然有机晶体或硫酸海洋可减少相关化工环节，但必须以实际资源和配方为准。稀有资源不等于无限供应，未建立稳定运输前保留必要的旧供应能力。

落地建立奇珍前哨时同时盘点当地其他奇珍，结合已有供应、下游需求和物流塔货槽安排对外输出，不只建设本次航行的目标矿种。大规模开采优先核对大型采矿机的解锁与制造成本、覆盖范围、可调采矿速度、电力和物流能力；尚未解锁时优先安排相关科研，先用必要数量的普通矿机打通缺失材料供应，再扩建大型采矿机。不能因已携带普通矿机而默认按普通矿机复制全部矿区，也不能把尚未开采的货槽配置视为持续供应。

## 航行准备与抵达

出发前查询 `player.flight`，核对推进器能力、核心能量、燃烧室燃料和翘曲器，准备着陆及返程储备。曲速启动需比较 `coreEnergy` 与 `warpStartEnergy`；背包有燃料不代表核心能量足够。能量不足时先补给或充能，也可接受普通航行。科研与手搓可并行，但要计入共同的能量和库存消耗。

长航程同时核对燃烧室的实际燃料及 `mecha.reactorPowerGenEnhanced`。`autoReplenishMechaFuel` 会按原生规则装入多种燃料，包括木材和植物燃料；仓内有核燃料棒不代表当前正使用它供能。补料后确认实际充能功率，并等待核心储能覆盖航行和落地；核心耗尽可能先触发 `insufficient_energy` 中断，不能依赖背包备用燃料必然在中断前自动接续。发生该终态时先补燃料、充能并重新读取位置，再恢复导航。

普通背包中的翘曲器不等于翘曲仓已补给。若 `warperCount:0` 且 `autoReplenishWarper:false`，使用 [机甲翘曲器补充命令](../interface/game-control.md#移动与采集) 后读回实际仓量和背包余量，再启动曲速；该命令不改变自动补充开关。

航行前的取料可能因交互范围失败，也可能因背包容量只转移部分数量。逐项核对实际 `movedCount`、背包和燃烧室库存；必需补给与起飞用任务依赖或 `stopOnFailure:true` 关联，补给失败后先解决范围或容量问题，不继续起飞。结合已完成航程的实际燃料消耗估算后续用量，不把请求数量或任务提交成功当成补给到位。

首次前哨的燃料预算应覆盖去程、落地后的施工与手搓、当地移动及返程；不能只按航行距离准备一组燃料。施工期间复查燃烧室余量，提前建立当地可持续补给或充电条件，避免成品已经备齐却无法返航。当前核心满电也不证明返程燃料充足。

优先用 `navigateTo` 指定星球及落点；长距离可传 `useWarp:true`。曲速条件不满足时会继续普通航行，通过结果 `warpUsed` / `warpStatus` 判断实际使用情况。目的地坐标、容差和低层飞行输入参数见 [飞行与导航](../interface/game-control.md#飞行与导航)。

导航期间每 5–10 秒查询同一任务，并核对运行结果 `appliedTicks`、阶段、距离、速度与能量；转向或避让时距离可以暂时增加。请求超时先重新查询原任务，不重复提交。游戏未暂停但输入 tick 停滞或长时间无进展时，先核对任务终态、燃料、原生订单与 `overrideReason`；控制器包装重建由执行器恢复。人工输入期间导航临时让出控制，输入释放及原生订单结束后同一任务从实际位置恢复；需要永久停止时取消任务。失败原因未改变时不循环重试，不同时下达固定飞行输入。

退出曲速不证明已经接近目的地。同一导航的远程航段在原生曲速完全退出至少60游戏tick、核心充能到90%后重新检查航向与原生启动条件并继续曲速；`warpStatus:recharging` 时保持任务，核对能量持续增长，不为重启曲速取消并重复下单。接近目标时保持普通航行与原导航完成着陆，实际到达以任务成功及接地状态为准。

原生启动能量门槛只证明可以启动，不保证全程续航。`PlayerMove_Sail.targetAtten` 会在恒星、行星等天体附近降低曲速速度；`UseWarpEnergy` 仍持续消耗启动和维持能量。低能退出后，不应刚超过启动门槛就反复尝试；结合剩余航程、原生耗能和天体衰减评估充能储备，充能时可继续普通巡航。天体衰减属于原生运行行为，不是目标距离或普通航速的启动下限。

长途预算同时计入核心容量和持续充能：从当前机甲读取 `warpStartPowerPerSpeed`、`warpKeepingPowerPerSpeed`、`maxWarpSpeed`、`reactorPowerConsRatio`，比较启动消耗、维持耗能与稳定巡航时实测的核心恢复速度；燃料充足也可能需要分段充能，不能据满核心承诺一次曲速抵达。曲速期间原生 `uVelocity` 可能仍保留普通航行速度，实际航程用连续 `uPosition` 与游戏 tick 差核对，避免把低 `uVelocity` 误判为曲速未推进。

落点应避开已有建筑。气态星先查采集器位置，选择附近可到达的悬停点；不要将采集器中心当作机甲落点。安装轨道采集器时选择符合原生间距要求的赤道位置，建成后检查实际气体库存增长。

固态星抵达以接地为准，气态星以目标附近低速悬停为准。太空点仅表示进入或穿过容差范围，不保证停车或持续驻留；取消、超时后仍可能保持速度或曲速，先读取真实状态，再决定退出曲速、制动或重新导航。不要重复相同失败指令消耗能源。
