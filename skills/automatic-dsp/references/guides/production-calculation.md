# 产线需求计算与增产剂选择

用于计算目标产量对应的机器、原料、增产剂和运输需求。Agent 选择配方、设备、生产边界及优化目标，[计算脚本](../../scripts/production-calc.mjs)负责算术、需求汇总和物料平衡。

## 数据与单位

使用当前存档对应的物品 ID、配方投入与产出、每轮秒数、设备相对配方的速度倍率及工作功率。物品速率统一为件/游戏秒，功率为 MW；件/分钟先除以 60。原型字段的单位换算与接口缺口见 [计算数据接入](../interface/game-state.md#产线计算数据接入)。记录数据版本、来源和人工假设，方便更换配方或设备后重算。

可将查询响应保存为 JSON，使用 `node scripts/prototype-to-recipe.mjs 快照.json 配方ID 设备物品ID 目标物品ID 每秒目标量` 输出 `production-calc.mjs recipe` 的输入。快照需包含配方的 `id type unlocked timeSeconds items results`，以及设备物品的 `id unlocked prefabDesc`；描述中选择 `isAssembler assemblerRecipeType assemblerSpeedMultiplier isLab labSpeedMultiplier workPowerW`。脚本保留所有投入与产物，拒绝特殊加工，不自动附加增产。

目录按页读取并按 ID 建立产物到配方的本地索引；连接游戏或切换存档后按需重读，解锁、库存和实例状态每次规划时重读。完整查询契约见 [原型与连接](../interface/prototypes-and-connections.md)。

计算前确定边界：哪些物品现场制造，哪些外部输入；原有产能中有多少已被其他产线占用；优化目标是尽快投产、节矿、节电、少建筑还是少占地。已有供应按稳定可分配余量抵扣，库存另算可维持时间。

## 普通制造公式与取整

适用于确定性、按周期消耗原料的制造配方，在满供电、满供料、输出畅通时计算长期平均值。设每轮耗时 `t`，设备速度 `s`，额外产出倍率 `y`，加速倍率 `a`，目标产物每轮数量 `q`，目标速率 `R`：

```text
每机每秒执行轮数 c = s × a / t
达到目标的每秒执行轮数 x = R / (q × y)
理论机器数 n = x / c
实际建造数 N = ceil(n)
目标工况原料 i 的需求 = x × 每轮投入 i
目标工况产物 j 的毛产出 = x × 每轮产出 j × y
取整后全机满载轮数 = N × c
全机满载用料 = N × c × 每轮投入
全机满载工作功率 = N × 设备基础工作功率 × 增产耗电倍率
```

**每个独立生产组的建筑数量向上取整。** 保留中间计算精度，最后展示时再四舍五入。共享上游先汇总需求后取整；物理上隔离的产线分别取整。脚本使用 JS 数值并直接 `Math.ceil`，极近整数边界的浮点误差可能保守多算一台；核对原始精度后处理，真实的小数需求仍向上取整。

例如教学配方每 2 秒消耗 3 A 产出 2 B，设备速度 0.75，目标 1 B/s：单机 0.75 B/s，需要 2 台。维持目标只需 1.5 A/s；两台全机满载则需 2.25 A/s，产出 1.5 B/s。

按目标工况供料能满足目标，取整留下的机器余量可能间歇工作。若希望下游取整后的设备持续满载，按它的 `fullLoad.inputs` 重新规划上游，并核对各段运输。把每一层的富余产能都强行向上传播会放大建设规模，按所需吞吐边界选择。

传送带并行条数也按 `ceil(所需流量 / 单条有效吞吐)` 算，并核对分拣器距离、堆叠、端口和汇流处的总流量。设备取整余量与应对供电/运输波动的余量分别说明。

## 增产剂口径

普通制造中，额外产出模式提高每轮产物数量，加速模式提高每秒执行轮数。相同目标下，额外产出降低原料需求；加速主要减少本工序机器数量。按配方支持的模式和实际输入喷涂状态取倍率。所有必要原料达到对应喷涂等级时才按完整加成估算；混合喷涂输入需按实际有效效果核算。

以下为基础游戏的增产剂参数，模组或版本调整时采用当前游戏数据：

优先查询 `cargo { incTableMilli accTableMilli powerTableRatio }` 获取当前倍率；数组按喷涂点数索引。喷涂次数和具体用途仍从物品原型与对应系统核实，不能把下表固定值覆盖到不同 Mod 的数据上。

| 增产剂 | 额外产出倍率 y | 加速倍率 a | 工作耗电倍率 | 基础喷涂次数 | 同级自喷后次数 |
| --- | --- | --- | --- | --- | --- |
| Mk.I | 1.125 | 1.25 | 1.30 | 12 | 13 |
| Mk.II | 1.20 | 1.50 | 1.70 | 24 | 28 |
| Mk.III | 1.25 | 2.00 | 2.50 | 60 | 75 |

额外产出模式取 `a=1`，加速模式取 `y=1`。耗电倍率作用于工作功率；待机、喷涂机、物流、供电损耗和燃料制造另计。

每秒需要新喷涂的物品数为 `S`、每件增产剂可喷 `K` 次时，增产剂消耗为 `S/K`。同级自喷且把自喷耗用也纳入供应边界时，持续产量需求为 `S/(K-1)`：例如 Mk.III 自喷后有 75 次，其中一次用于维持自身喷涂，净服务其他物品 74 次。`S/74` 只处理自喷，不包含制造增产剂原料的喷涂需求，后者仍需进入供应链。已由外部供应的喷涂物品，在当前工序只计新增喷涂。

增产剂、发电燃料的生产也可能消耗增产剂及电力，形成反馈环；按净产出求平衡。循环启动还需要首批物料、电力和回流缓冲，稳态平衡只描述运行后的供需。

科研矩阵喷涂增加科研进度；燃料、透镜、火箭与太阳帆、分馏等按专用机制建模。它们与普通制造的 `q × y` 模型分开计算；尤其分馏的循环带吞吐与净氢消耗是两项不同需求。

## 比较增产与加速

为同一交付目标计算无喷涂、可用等级的额外产出、加速候选，比较整条供应链的原料、设备、功率、增产剂与部署成本。已有设备、可用电力、原料距离及运输容量决定本次扩产的实际代价。

可用下面的简化式初筛：设不喷涂时，上游单位成本为 `U`，本工序单位成本为 `L`，暂略增产剂、供电变化和整数效应，额外产出成本为 `(U+L)/y`，加速成本为 `U+L/a`。Mk.III 下前者更优的条件为 `U>1.5L`。这个阈值用于理解成本结构；最终用完整链路和整数设备复算。层数本身无法表示上游成本。

取整后的最后几台可以比较不同模式的组合。例如将部分加速设备换为增产设备，仍达到目标时，可能减少上游需求。把每组设备按各自模式计算并汇总；模式选择与布局由 Agent 决定。

## 多产物、循环与共享供应

在同一供应边界内汇总所有目标及中间需求，用副产物先抵扣实际可达的需求。保留每种物品的毛产出、毛消耗、外部输入、净交付和剩余，回流物品同时出现在两侧。例如每轮投入 2 氢、产出 3 氢，净增加只有 1 氢，而运输仍需承担完整回流量。

固定配方和增产模式后，设每秒执行轮数为 `x_r`，物品 i 在配方 r 中的净产出系数为 `A_ir`，外部输入为 `b_i`，交付需求为 `d_i`：

```text
Σ A_ir × x_r + b_i = d_i + 剩余_i
x_r >= 0，剩余_i >= 0
机器数_r = ceil(x_r / 每机每秒执行轮数_r)
```

把增产剂消耗也写入投入系数。外部输入需有来源和容量限制；每种剩余需有持续出口。副产物没有稳定消耗或输出时，对该物品约束剩余为零。多来源、多产物可按目标成本做线性规划；整数设备优化是进一步的问题。脚本的 `balance` 用于核验 Agent 或求解器给出的执行速率，返回所有缺口与剩余。

跨星球无法输送的副产物应分开边界计算。库存增长只提供暂时缓冲；副产物作燃料时，其消耗受电网实际负载限制。

## 使用脚本

运行环境为 Node.js，使用内置模块。按下述输入约定准备 JSON 文件，在 skill 根目录运行（将路径替换为实际输入文件）：

```sh
node scripts/production-calc.mjs recipe /path/to/recipe.json
node scripts/production-calc.mjs chain /path/to/chain.json
node scripts/production-calc.mjs balance /path/to/balance.json
```

支持用 `-` 从标准输入读取 JSON。例如在 Bash/Zsh 中直接计算上述教学配方：

```sh
node scripts/production-calc.mjs recipe - <<'JSON'
{"targetItem":"B","targetPerSecond":1,"recipe":{"timeSeconds":2,"machineSpeed":0.75,"activePowerMW":0.3,"inputs":{"A":3},"outputs":{"B":2}}}
JSON
```

结果应为 2 台设备，目标用料 1.5 A/s，全机满载用料 2.25 A/s。以下是计算器输入约定，任务本身可自由组织：

| 字段 | 含义 |
| --- | --- |
| `recipe.inputs` / `outputs` | 物品 ID → 单轮数量；示例用字母表示教学物品 |
| `timeSeconds` / `machineSpeed` | 原始配方秒数 / 相对配方速度，不含所选增产模式加速 |
| `activePowerMW` | 可选，未增产时设备工作功率；缺省时功率结果为 null |
| `proliferation` | 可选；省略表示不使用增产剂 |
| `proliferation.mode` / `bonus` | `extra` 或 `speed`；对应加成小数，例如 0.25 或 1 |
| `powerMultiplier` / `item` | 增产后的工作耗电总倍率 / 增产剂物品 ID |
| `spraysPerItem` / `selfSpray` | 实际每件喷涂次数 / 是否计入同级自喷的自身消耗 |
| `sprayedInputs` | 可选，单轮需在本边界内新喷涂的输入数量，默认全部原料；已喷原料的加成由调用者核实 |

`recipe` 输入 `recipe`、`targetItem`、`targetPerSecond`，返回目标流量 `target`、建筑整数 `machines` 和全机满载流量 `fullLoad`。

`chain` 输入 `targets`（物品 ID → 件/秒）和选定的 `recipes`，支持单产物无环依赖，汇总共用上游后逐工序取整。缺少制造配方的物品列为 `externalInputs`，作为待核对的外部供应需求；该输出还需与采矿、进口或已有产线能力比较。它按目标流量展开，上游不会自动追随所有富余机器满载。计算边界包含增产剂自循环或多产物时使用 `balance`。

`balance` 输入 `targets`、`imports` 和 `steps`；每步包含 `recipe`、`cyclesPerSecond`。它按给定的计划执行速率核算，输出每项 `shortage` / `surplus`，供修正配平及安排副产物出口。不同生产组分别取整，功率结果是每组满载工作功率，辅助设施另计。

计算结果是规划依据。投产后用实际游戏时间窗口检查目标端产出、各级库存、电力和运输；统计口径见 [查询及计量](../interface/game-state.md)。
