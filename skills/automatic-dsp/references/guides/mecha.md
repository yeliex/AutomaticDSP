# 机甲能源、移动与手工作业

## 能源与背包

普通背包与物流背包是独立库存；物流格需要配置物品及补货/回收阈值，自动配送由原生物流配送器执行。跨库存整理使用 transferInventoryItem，查看 movedCount；普通背包满时仍可能收到物流格或手中返还，核对三处数量及增产点。配置及查询见 [游戏控制](../interface/game-control.md#配送器物流背包与指定转移) 和 [游戏状态](../interface/game-state.md)。

机甲补给默认使用自动配送：启用物流背包，通过 `setDeliverySlot` 更新当前所需物品、`requireCount` 和 `recycleCount`，供货配送器默认同时供应和回收，规则见 [物料供应与仓储](production.md#物料供应与仓储)。换物品前先将旧格库存自动回收或转入普通背包，确认格位为空后再修改；按原生阈值步长设置且补货阈值不高于回收阈值。设置后等待并核对实际到货或回收，不把配置成功当成交付完成。缺料先查供货库存、配送范围、电力和机器人，不默认直接调用手动取货接口；仅在尚未解锁、配送设施不可用或紧急启动确需时手动补给。

定量取放优先使用已有数量接口：背包与手中之间用 `transferInventoryItem` 拆分指定数量，储物仓用 `transferStorageItem`，运输站货槽用 `transferStationItem`。生产建筑定量投料可先将所需数量移到空手中，再用 `entityFastFillIn(fromPackage:false)`；手中原有同种物品也会被填入，须先处理原有库存。拆分和填入放在同一有序任务中，随后核对实际转移和手中余量。不要为少量补料使用 `fromPackage:true`，它可能一次投入背包中大量兼容原料。各接口的数量上限、部分成功与取回限制见[背包、仓储与制造](../interface/game-control.md#背包仓储与制造)。

快速填充有原生批次限制，拆到手中的数量不等于实际投入量；以 `movedCount` 和燃料槽库存计算启动缓冲，确保自动供料接通前不会耗尽。具体限制见 [背包、仓储与制造](../interface/game-control.md#背包仓储与制造)。

背包满时优先整理或转存需要保留的材料。丢弃会生成可拾回的垃圾；拾取前检查所属星球、当前位置与背包余量。不要把“本星球垃圾”当成“当前能捡”，也不要将永久清理用作腾背包或回收物品；原生清理是全局操作，会影响其他星球。查询与命令见状态、游戏控制接口的垃圾说明。

批量递归手搓前检查普通背包的实际空格与堆叠余量，为中间品和最终产物留空间；物流背包中的现货先按需转入，不能将其当成制造器已经可用的材料。制造等待超时不会取消原生制造，重试前查询 `forge.tasks`、三处库存和垃圾，避免重复制造。等待预算参考原生 `forge.totalTime` 或任务结果的 `forgeTotalTime`，并计入实际游戏推进速度。

用户允许丢弃低价值杂物时，可主动清掉当前无用、容易补回的零散物品，保留目标所需材料、燃料及施工物资。丢弃后必须检查垃圾收尾：刷新全局 `trash`，若全部都是已决定不要的物品，调用 `clearTrash(scope:"all")` 并确认垃圾数量归零；存在需保留或来源不明的物品时先核对并回收需要的部分，不能用全局清理误删其他星球的物资。拆除或满包产生的溢出物也按此流程处理，拾取成功须以实际入包和垃圾减少为准。

移动、人工采集、建造和背包制造依赖机甲能源，能源不足会降低行动效率。检查当前储能、燃烧室和行动距离，安排补给；用燃料热值、机甲相关加成、可获得性和携带空间比较当前可用燃料。长途行动还需计入途中补给条件。

`reactorPowerGen` 是基础燃烧功率，当前燃料及增产加成后的功率读取原生 `reactorPowerGenEnhanced`，另计 `corePowerGen`。用游戏 tick 与核心能量增量核对实际恢复速度；普通航行有持续推力输入不等于持续耗费加速能量，满速直线的原生耗能取决于速度修正量。不能仅据推力标志或基础功率认定导航妨碍充能。

制造、取料或拆除设施可能改变背包物品与占用空间，提前留出容量，之后核对实际获得数量。取用产线库存时，考虑对持续生产的影响；仓储管理见 [物料与仓储](production.md#物料供应与仓储)。

储物仓取放的命令下发范围与实际交互范围不同：在下发范围内仍可能先触发原生靠近。取料长时间不完成时，核对角色位置、目标距离、任务状态和实际转移量；若角色持续停在密集建筑前，改从可通行的近处站位取料，不重复提交相同靠近路径。取消后只重排未完成取料，已取材料不再重复领取。

递归手搓的中间产物也占背包格，不能只给最终建筑留一个格子。首批外星货物带回后，先用单品仓储释放空间，再批量制造设备；制造任务成功仍需检查背包与垃圾，产物可能因满包被抛出。满包后先转存至合适的已有库存，或用目标确实需要的加工减少占格，再回收产物；不要继续制造新的仓储。原生拾取要求手中为空，不能通过手持一整格物品腾位后直接拾取。

初期燃料候选包括木材、植物燃料、煤矿和飞行仓回收的燃料棒。优先使用现有可用燃料，再比较补采或加工所需时间；煤矿还可能用于生产，分配时保留相应供应。

燃料总能量决定可持续行动的预算，燃烧室恢复功率影响连续高耗能动作。跨水面或长途飞行前同时检查这两项，并为返程保留补给。

太空中仅剩散氢作应急燃料时，若随身有钛块且液氢棒配方已解锁，可在保持原导航运行的同时用独立手搓队列压成液氢棒。当前原生配方19为10氢和1钛产2棒，每棒54MJ、reactorInc2；相比散氢每件9MJ、reactorInc1，同批氢加工后基础热量增加20%，且实测燃烧功率3.2→4.8MW。先读当前原型、可制造量、燃烧室余量及制造耗时，保留首批产物完成前的能源；查询同一制造任务确认完成和实际燃料切换，不重复制造或导航。

自动补充可能同时投入多种燃料；燃烧室内有高级燃料不代表正在使用它。混合燃料时核对 `reactorItemId` 和 `reactorPowerGenEnhanced`，以当前实际燃烧物与净储能变化评估持续航行能力。

已解锁无线输电塔时，可利用接入有余量电网的塔为机甲充电。优先复用施工区或取料点附近的塔，将等待制造、观察产线等停留安排在有效充电位置；高耗能施工前结合当前储能判断是否值得补电。需要新建时，同时比较输电连接、建筑供电覆盖、机甲充电便利与建设成本，不为每处作业点固定配塔。

无线输电塔不发电，机甲充电会增加电网负载。检查电网连通和供需，并在停留前后读取 `mecha.coreEnergy`、`coreEnergyCap` 及游戏 tick，核实净恢复速度；燃料燃烧和同时进行的动作也影响储能变化，不能把全部增量归因于无线充电。输电连接距离、建筑供电半径与机甲实际充电条件应分别核对。离开电网仍需燃料，燃烧室为空也不等于机甲当前电量为零。

用 `items(where: { heatValueJ_gt: 0 })` 分页发现候选，读取 `heatValueJ fuelType reactorInc stackSize productive`，再与实际库存和燃烧室接受规则关联。热值是每件基础能量，`reactorInc` 是机甲燃料功率加成；实际恢复能力另查 `mecha.reactorPowerGenEnhanced`，喷涂和当前燃料状态另计。不要将发电建筑额定功率当作燃料固定功率，详见 [原型属性](../interface/prototypes-and-connections.md)。

## 移动与人工采集

结合当前位置、目标距离和机甲能源安排移动。行星上远距离移动应使用 `navigateTo`，指定当前星球 ID 和局部 `position`，通过原生飞行抵达；`moveTo` 只用于短距离接近或交互前微调，不用连续步行任务代替长距离飞行。先核对飞行科技、燃料和核心能量；飞行尚未解锁或能源不足时，先处理限制，确需步行才分段移动并设置 `timeoutSeconds`。接近目标后按实际位置继续操作。

同星球 `navigateTo` 当前使用近地 Fly，不会自动升空进入 Sail，也不会因 `useWarp:true` 转成同星球太空捷径。不要为此临时指定别的星球或伪造太空目标。同星球的距离按地表弧长理解：用两局部位置方向夹角乘行星半径估计，避免用穿过行星的直线距离低估行程。

`navigateTo` 可从水面漂浮状态 `Drift` 通过原生起飞输入继续；低层 `takeOff` 仍要求 `Walk`。遇到 `invalid_movement_state` 时先查询真实状态与输入推进，不在状态未变时重复提交。

长途导航优先 `useWarp:true`，定期核对距离、阶段、核心能量与翘曲器；低能退出后同一导航在充分充能时恢复曲速，接近目标改用普通航行。人工操作期间临时让出控制，输入释放与原生订单结束后恢复；要永久停止应取消任务。科研、手搓独立推进，后续移动、采矿和建造下达等待导航释放，不能用这些命令强行覆盖航线。

导航退出曲速后按剩余航程估算恢复电量，包含原生启动、维持耗能、近天体衰减及余量；长程分段等待上限为容量90%，短程不要求充到90%。保持同一任务等待自动恢复，不为绕过充能条件取消重下。估算不抵扣尚未产生的反应堆充电，也不保证任意避让航路一次曲速到达。

远程曲速回充阶段导航暂停额外加速，保留原生转向及惯性航行，优先恢复翘曲电量。用核心能量差和游戏 tick 测量净恢复速度，不能用燃烧室额定功率直接估算等待时间；保持原任务，不再为省下普通巡航加速而取消并手动滑行。普通固态星巡航对准后持续请求原生最大加速，不随速度抬高全程制动储备；实际加速度仍受原生上限及可用电量限制。

固态星导航保持最高普通航速接近，提前朝可见的指定落点修正航向，高速进入地表后补齐近地航段。接近移动卫星时，若连续多次观测仍无法接近，核对能源、人工接管及避让状态，并同步读取机甲宇宙位置、速度和目标行星的当前及下一 tick 宇宙位置，分析相对运动。根据原始状态定位原因，不把取消导航、手动截获或反复重下同一目标作为常规恢复步骤；不能直接修改位置或速度。

水面稳定漂浮 `Drift` 可满足导航到达条件，不应仅凭移动模式判断失败；核对任务终态、落点距离、高度与速度。若任务确实失败但已在交互范围内，可继续原操作而不重复导航；依赖失败导航而跳过的命令，确认尚未执行后再重新下达。

岸边可能短暂显示 `Walk`，但起飞立即进入 `Drift`；此时先核对实际地形高度和接地状态。原生输入仍不能恢复时，优先走到已确认的干燥空地；具备地基和沙土预算时，也可原生整平当前小块落脚处，再起飞并确认 `Fly`。不要仅凭一次 `Walk` 状态反复导航。

步行和飞行落点都选在设备外的可通行空地；落点位于建筑占地或被建筑阻挡时，原生靠近可能停在容差外，飞行也可能悬在建筑上方而无法接地。连续观察位置、距地高度和接地状态不再变化后，取消受阻移动，依据实际实体位置选择绕行点或空地落点，不重复下达同一目标。建造和实体取放已有范围内原生靠近能力，不必先移动到建筑中心。

自然碎石和植被也会阻挡步行。移动订单未到达、连续观测位置不变且局部速度接近零时，查询附近 `vegePool` 的原始位置并结合现场核对障碍；可原生采集清除，或选择绕行点。已解锁飞行且能源充足时，长距离或反复受阻的本星球移动优先使用 `navigateTo` 到已确认的空地，避免沿同一受阻直线反复步行直至超时。

人工采集适合眼前的小量缺口。先检查背包和可取用仓储，再按距离、行动时间和缺失数量选择采集对象。矿脉、地面资源和飞行仓按各自对象类型处理，采集后核对实际获得物品与对象剩余状态。

持续消耗可转为自动化，矿机覆盖与运输规划见 [建设与运输](production.md#连接与吞吐)。新存档的回收与初始材料安排见 [开局经验](opening.md)。

## 背包制造

优先让原生制造、科研与玩家行动并行。通常给 `craftInventory` 传 `waitForCompletion:false`，给 `researchTech` 传 `waitForUnlock:false`；这两类操作默认自动分流，已有长任务运行时也可及时下达，无需 `immediate:true`。成功入队后继续移动、采集、建造或观察工厂；只在后续操作真正依赖产物或科技时等待库存/解锁条件。科研可以在材料制造完成前入队，满足科技前置后由游戏等待并消耗材料，LLM 不必先等全部材料完成。

手搓建筑、运输机和运输船前，先按配方检查所需中间产物、现有产线和仓储库存，尽量直接取用已生产的齿轮、磁线圈、电动机、电磁涡轮、处理器等，避免将大量时间耗在递归制造中间产物。比较取料往返时间与省下的制造时间，按实际缺口取料，并为科研及持续生产保留供应；不能仅因原矿足够就直接排入大批递归手搓。

后续制造需要前一条命令的产物时，显式用 `dependsOn` 等待完成，或确认实际库存后再下单。尚在原生手搓队列中的产物不能算作可用库存，否则后续命令可能重新递归占用原矿并报缺料。批次失败或取消后先核对原生 `forge.tasks` 和实际背包；已经产出的材料、建筑可能仍然保留，只补尚未完成的部分。

常用建筑与运输工具的需求持续后，采用 [建筑超市与补货](production.md#物料供应与仓储)，优先复用现有产线，减少临用手搓。

批量递归手搓会先制造一大批前置材料，延迟第一件最终产物。开局优先按“马上能启用下一步”的小批量下单，例如先做一座建筑或一项研究的最低材料，投入使用后再补下一批；不要为了整条产线一次预制大量材料。不要一口气把全部小批次塞满队列，应随着库存和需求推进补充，保留临时调整空间。分批不缩短总加工时间，但能提前得到首批可用物品。

等待时查询 `forge { totalTime actualReplicateSpeed tasks { recipeId count tick tickSpend parentTaskIndex } }` 和 `metadata.gameTick`，区分递归中间材料加工、缺料、能源不足及暂停。向用户报告当前物品和剩余时间。只有明确需要撤销时才用 `removeForgeTask`，移除前刷新索引和配方，移除后重新清点退款与关联任务。

从目标物品反查可用手工配方，核对解锁、原料和制造数量。手搓适合少量、紧急、能快速解锁关键能力的物品；持续重复的需求可投入设备、供电和连接实现自动化。比较准备时间与后续节省的操作成本，选择适合当前目标的方式。

对象识别和状态字段见 [查询](../interface/game-state.md)，移动、采集、补燃料和制造参数见 [游戏控制接口](../interface/game-control.md)。
