# 机甲能源、移动与手工作业

## 能源与背包

背包满时优先整理或转存需要保留的材料。丢弃会生成可拾回的垃圾；拾取前检查所属星球、当前位置与背包余量。不要把“本星球垃圾”当成“当前能捡”，也不要将永久清理用作腾背包或回收物品；原生清理是全局操作，会影响其他星球。查询与命令见状态、游戏控制接口的垃圾说明。

移动、人工采集、建造和背包制造依赖机甲能源，能源不足会降低行动效率。检查当前储能、燃烧室和行动距离，安排补给；用燃料热值、机甲相关加成、可获得性和携带空间比较当前可用燃料。长途行动还需计入途中补给条件。

制造、取料或拆除设施可能改变背包物品与占用空间，提前留出容量，之后核对实际获得数量。取用产线库存时，考虑对持续生产的影响；仓储管理见 [物料与仓储](production.md#物料供应与仓储)。

初期燃料候选包括木材、植物燃料、煤矿和飞行仓回收的燃料棒。优先使用现有可用燃料，再比较补采或加工所需时间；煤矿还可能用于生产，分配时保留相应供应。

燃料总能量决定可持续行动的预算，燃烧室恢复功率影响连续高耗能动作。跨水面或长途飞行前同时检查这两项，并为返程保留补给。

已解锁无线输电塔时，可利用接入有余量电网的塔为机甲充电。优先复用施工区或取料点附近的塔，将等待制造、观察产线等停留安排在有效充电位置；高耗能施工前结合当前储能判断是否值得补电。需要新建时，同时比较输电连接、建筑供电覆盖、机甲充电便利与建设成本，不为每处作业点固定配塔。

无线输电塔不发电，机甲充电会增加电网负载。检查电网连通和供需，并在停留前后读取 `mecha.coreEnergy`、`coreEnergyCap` 及游戏 tick，核实净恢复速度；燃料燃烧和同时进行的动作也影响储能变化，不能把全部增量归因于无线充电。输电连接距离、建筑供电半径与机甲实际充电条件应分别核对。离开电网仍需燃料，燃烧室为空也不等于机甲当前电量为零。

用 `items(where: { heatValueJ_gt: 0 })` 分页发现候选，读取 `heatValueJ fuelType reactorInc stackSize productive`，再与实际库存和燃烧室接受规则关联。热值是每件基础能量，`reactorInc` 是机甲燃料功率加成；实际恢复能力另查 `mecha.reactorPowerGenEnhanced`，喷涂和当前燃料状态另计。不要将发电建筑额定功率当作燃料固定功率，详见 [原型属性](../interface/prototypes-and-connections.md)。

## 移动与人工采集

结合当前位置、目标距离和机甲能源安排移动，接近目标后按实际位置继续操作。

人工采集适合眼前的小量缺口。先检查背包和可取用仓储，再按距离、行动时间和缺失数量选择采集对象。矿脉、地面资源和飞行仓按各自对象类型处理，采集后核对实际获得物品与对象剩余状态。

持续消耗可转为自动化，矿机覆盖与运输规划见 [建设与运输](production.md#连接与吞吐)。新存档的回收与初始材料安排见 [开局经验](opening.md)。

## 背包制造

优先让原生制造、科研与玩家行动并行。通常给 `craftInventory` 传 `waitForCompletion:false`，给 `researchTech` 传 `waitForUnlock:false`；这两类操作默认自动分流，已有长任务运行时也可及时下达，无需 `immediate:true`。成功入队后继续移动、采集、建造或观察工厂；只在后续操作真正依赖产物或科技时等待库存/解锁条件。科研可以在材料制造完成前入队，满足科技前置后由游戏等待并消耗材料，LLM 不必先等全部材料完成。

批量递归手搓会先制造一大批前置材料，延迟第一件最终产物。开局优先按“马上能启用下一步”的小批量下单，例如先做一座建筑或一项研究的最低材料，投入使用后再补下一批；不要为了整条产线一次预制大量材料。不要一口气把全部小批次塞满队列，应随着库存和需求推进补充，保留临时调整空间。分批不缩短总加工时间，但能提前得到首批可用物品。

等待时查询 `forge { totalTime actualReplicateSpeed tasks { recipeId count tick tickSpend parentTaskIndex } }` 和 `metadata.gameTick`，区分递归中间材料加工、缺料、能源不足及暂停。向用户报告当前物品和剩余时间。只有明确需要撤销时才用 `removeForgeTask`，移除前刷新索引和配方，移除后重新清点退款与关联任务。

从目标物品反查可用手工配方，核对解锁、原料和制造数量。手搓适合少量、紧急、能快速解锁关键能力的物品；持续重复的需求可投入设备、供电和连接实现自动化。比较准备时间与后续节省的操作成本，选择适合当前目标的方式。

对象识别和状态字段见 [查询](../interface/game-state.md)，移动、采集、补燃料和制造参数见 [游戏控制接口](../interface/game-control.md)。
