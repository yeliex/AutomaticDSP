# 新建游戏、初始化与存档

## 启动与选择对局

先按 [Mod 使用说明](../mod-usage.md)完成安装与连接，随后选择对局。对局控制参数见 [游戏管理接口](../interface/game.md)。

Steam 版启动或重启优先通过已安装 Steam 的命令行 `steam.exe -applaunch 1366540`，路径从实际安装信息确认；无需先打开并点击客户端界面。避免直接启动游戏可执行文件导致 Steam 未初始化。不要重复启动已运行的游戏；启动后用 `GET /game` 等待菜单就绪，再通过 Mod 载入存档。更新 Mod 前先保存、正常退出游戏并确认进程结束。

先确认当前运行状态，再根据任务选择：

| 当前情况 | 初始化动作 |
| --- | --- |
| 已在对局中 | 核对存档、模式与用户目标，沿用当前进度 |
| 菜单中继续旧档 | 读取存档列表，按用户指定的存档加载 |
| 菜单中新建对局 | 按目标确定种子、星数、资源倍率、和平/战斗、沙盒及序幕选项，再创建游戏 |
| 正在加载 | 等待加载完成，确认进入预期对局 |
| 暂停或序幕中 | 按当前状态恢复游戏进程，序幕按用户选择继续或跳过 |

## 新建游戏

### 确定对局条件

结合用户目标选择开局条件，保留实际采用的参数，方便后续恢复或复现。

| 条件 | 选择时考虑 |
| --- | --- |
| 星系种子与恒星数 | 用户指定的星系、复现要求，以及后续资源探索和戴森球选址范围 |
| 资源倍率 | 资源枯竭压力、扩产规模和补充矿区的频率 |
| 和平或战斗模式 | 是否包含黑雾、防御建设和战斗资源投入 |
| 沙盒模式 | 按用户约定选择，完成目标时采用对应规则衡量结果 |
| 序幕 | 需要体验降落过程则保留；直接开始操作可跳过，随后仍检查落地现场 |

参数名称、默认值、范围及创建示例见 [创建新游戏](../interface/game.md#post-game创建新游戏)。提交后核对实际对局配置，确认进入预期星系和模式。

### 确认落地与时间推进

新建请求开始执行后，等待加载完成，检查当前行星、机甲位置及序幕状态。若仍在序幕中，按选定的开局方式等待或跳过；暂停时先恢复游戏，再执行依赖时间推进的采集、制造、研究和建造。

接口的就绪标记与创建响应含义见 [游戏管理接口](../interface/game.md)。当前暂停恢复通过游戏界面处理。

### 观察落地现场

第一次观察用于确定手里已有的能力和物资：

| 观察内容 | 用途 |
| --- | --- |
| 当前行星、机甲位置与附近飞行仓 | 确认落地位置，定位可回收的开局物资 |
| 背包物品、燃烧室物品与机甲储能 | 判断可用材料、燃料和接下来的行动预算 |
| 已解锁科技与当前研究 | 判断能直接制造、建造或推进的科技 |
| 已有建筑与附近矿脉 | 识别已有进度，准备后续采集和产线选址 |

先读取这些局部信息，规划具体动作时再补充所需对象。查询示例见 [最小观察示例](../interface/game-state.md#最小观察示例)。

### 回收飞行仓并重新清点

即使跳过序幕，也先检查落地行星的飞行仓。回收得到的燃料和基础材料会改变后续缺口，优先把这批物资纳入计划。

1. 定位现场飞行仓，使用当前对象执行采集，等待回收结果。
2. 重新读取背包和机甲燃烧室，确认实际获得的物资。
3. 补充机甲燃料，检查燃烧室和储能变化，为移动、手搓和建造准备能源。
4. 根据刷新后的库存与科技需求计算缺口，再安排采矿、手搓和研究。

查不到飞行仓时，结合当前行星、落地进度和背包判断是否已经回收。采集返回目标不存在时同样刷新现场；对象消失本身不足以证明本次获得了物资。

对象识别见 [游戏状态查询](../interface/game-state.md#最小观察示例)，回收与补燃料参数见 [移动与采集](../interface/game-control.md#移动与采集)。

### 转入科技与产线建设

确认已进入预期对局、落地物资已清点、机甲能源可用后，根据当前库存选择下一步。例如磁铁与铜块足够制造电磁学所需磁线圈时，可以先手搓推进研究；科技奖励也计入后续建设预算。

接续 [开局到第一条基础产线](opening.md)安排科研和建设。加载已有存档时同样先核对现场，根据现有能力接续 [目标与科研](goal-planning.md)。

## Windows 文件位置

默认数据根目录为 `%USERPROFILE%\Documents\Dyson Sphere Program`，存档位于其 `Save` 子目录。

安装目录下的 `Configs\path.txt` 配置数据位置。优先采用 `GET /game/saves` 返回的 `saveFolder`；需要检查重定向时，在游戏主机读取配置。

| 子目录 | 用途 |
| --- | --- |
| `Achievement` | 成就 |
| `Blueprint` | 蓝图；部分环境或资料使用 `Blueprints`，以实际目录为准 |
| `Customize` | 自定义机甲等数据；机甲蓝图常见于 `Customize\Mecha` |
| `Save` | `.dsv` 存档 |

文件操作需要访问游戏主机的文件系统。写入前核实目录、类型与格式，保留已有同名文件。

## 蓝图准备

根据工厂、戴森球或机甲蓝图类型，将兼容文件准备到对应位置。文件放置、游戏内应用、实际建设分别记录状态。

戴森球蓝图可在其编辑界面粘贴代码。当前自动导入和编辑接口待支持；文件准备完成后记录待应用状态。
